# 视频发布异常恢复

本次对应审计 F01、F11、F12、F13、F18。配额容量问题 F06 不在此变更范围。Cloud、Agent 与网页应协同更新；本文件描述源码行为，不表示已部署或已完成真实 YouTube 验收。

## 1. 授权异常保留工作

- 第一次普通视频 API 401 触发一次受控短期令牌刷新。GET 最多重新读取一次；上传、封面和其他写请求不在 HTTP 层重放，交还 Runner 沿原检查点核对后处理。刷新网络故障继续保留原授权。
- 仍无法确认授权的独立发布账号进入 `needs_reauthorization`。任务、计划、Profile、已上传 videoId 和本地检查点保留；新 API 工作等待同频道重新授权。网页明确提示 YouTube 已确认的排期仍可能执行。
- 只有失效后发起并由原浏览器完成的新 Cloud OAuth 事务能恢复该账号。服务端随机 epoch 隔离失效代际；旧事务、迟到 Agent 注册、旧令牌状态同步不会解除新失效。重新授权选择其他频道仍被拒绝。
- Agent 完成确认丢失时，账号保持需要重新授权；用户可再次使用原账号的“重新授权”，不需要删除账号或源素材。恢复账号后，原任务由用户点击“继续”沿原视频恢复。
- legacy 任务没有独立账号状态：授权异常保留为“需要处理”，不自动创建清理记录、不删除同实例其他发布任务，也不占用撤销清理锁。原同频道授权入口仍可使用，授权后继续原任务。
- 用户明确删除发布账号仍走原清理及撤销流程；这与临时授权失败分开。过期的 API 观察数据继续遵守现有清除规则。

## 2. 同名批次的下一次使用

归档完成只终结该轮已存在的计划和源文件引用。真实扫描在 Inbox 中发现重新建立的同名目录时，可以生成新的计划。Cloud 的 `sourceArchivedAt` 回执区分旧目录生命周期；新包版本不被旧归档任务当作重复上传。

旧草稿仍带归档标记，不能指向后来放进同名目录的文件。归档处理中仍禁止再建立同名计划；确认仍检查当前源版本。同版本再次发布继续要求明确选择已完成原任务并同意再次发布。第二轮归档不会改写第一轮的归档目的地。

## 3. 活动任务改期

预上传窗口只限制尚未交付且没有上传事实的首次工作。准备或上传已经开始后，即使新日期超出窗口，新的任务修订也会及时投递给 Agent；原 videoId、会话和暂停意图保留。

Cloud 保存日期不代表 YouTube 已完成改期。设备离线、旧写请求已经在途或公开时刻已经到达时仍须等待实际回执，必要时在 Studio 核对。真实平台公开竞态和网络时序尚未验收，不承诺离线时一定阻止旧排期。

## 4. 修复原视频设置

已上传且“需要处理”的任务可以展开“操作与详情 → 修复发布设置”，重新选择频道播放列表、清空失效列表、修正固定封面文件名或跳过封面，然后保存并继续原任务。

修复只接受播放列表、缩略图方式和文件名三个字段。源视频、频道、发布账号、文案和公开方式仍为原快照，videoId 保留，不建立第二次上传。Agent 先核对原视频；已经公开则按真实公开结果收尾，不再应用修复写操作。已完成列表步骤保留，失败输入保留。此入口要求 Agent 声明 `publishing-recovery-v1`；旧 Agent 得到明确升级提示。

## 5. 恢复自动排期

“恢复自动排期”提交当前编辑草稿的全部字段，只清除固定时间并切换为自动排期。当前标题和说明随请求保存；仅请求成功后关闭。失败或没有成功结果时，面板和未保存输入均保留。
