# LiveNest 0.1.6

网页或客户端设置中删除设备绑定后，设备不再出现在客户和管理员列表。已登录客户端下一次成功核对云端时自动解除旧绑定，回到配对入口；离线客户端恢复网络并登录后同步。原 OBS、素材和本地配置保留，重新添加电脑并粘贴新配对码即可连接，不需要管理员恢复旧设备。

删除是解除设备控制关系，不是远程擦除磁盘，也不会隐式停止 OBS。已接收任务排空后才提交本机解绑，磁盘失败保留旧配置并允许重试。云端仅保留拒绝旧凭据所需的内部记录；已删除身份不能被旧配对入口复活。没有删除的其他客户设备仍受权限保护。网络、5xx 或不匹配的凭据不能触发自动解绑。

## 同时修复

- 状态读取使用结构化错误，区分客户登录失效、账号权限、本机通信、网络和保存失败。
- 读取失败不再同时显示“正在读取”；重试只读取状态，不执行电脑诊断或直播操作。迟到的轮询不能覆盖新操作结果。
- 诊断复制使用受限 Electron 剪贴板接口，只复制经过校验的脱敏摘要，不依赖被禁用的浏览器剪贴板权限。
- 登录主按钮和辅助按钮分组留出间距，支持 780px 窗口和键盘操作。
- 重新配对使用新设备凭据；旧任务记录保留但不向新设备上报。

## 发布与验证

先部署兼容云端，再发布新客户端。旧客户端保留原接口；新版需要云端新增绑定核对接口，旧云端返回错误时保留身份，不猜测已删除。完整 verify、Windows 实际安装/覆盖升级/保留数据卸载 CI、隔离 Electron 和模拟界面验收的最终证据记录在 PR。

双 OBS 验收分别覆盖：真实隔离桌面的两个便携 OBS 启动、独立端口、WebSocket 场景与媒体源校验、重复检查不新增实例；真实云端路由在合成数据中完成双实例删除、重新配对、建立会话和网页实例列表核对。两项组合不冒充用户生产账号的实际配对。

截图位于 [screenshots/binding](screenshots/binding)，均明确标记为模拟故障或隔离验收。没有使用真实 OAuth、实际开播或真实用户数据迁移作为自动测试。生产部署只切换代码，保留账号、设备、频道和现有配置；回退只回退代码。

## 本地验收证据

- 完整 `npm run verify` 通过（51 个测试文件、360 项测试、8 项部署测试），随后新增的邀请结果回归通过；最终提交的完整计数以 CI 为准。
- `npm run desktop:build` 与打包产物检查通过。
- `node scripts/desktop/binding-acceptance.mjs` 通过真实 Electron 结构化错误和受限剪贴板测试，以及 780/1280px 模拟界面检查。
- `node scripts/desktop/two-obs-acceptance.mjs` 在独立目录中实际创建并启动两个 OBS，端口为 4455/4456，场景与媒体源校验通过，重复准备未新增实例；测试结束只关闭该目录的测试 OBS。
- `tests/desktop-binding.test.ts` 的 13 项隔离回归通过，包括双实例重新配对、云端会话与列表、历史撤销、两端删除、权限、网络、落盘失败及旧配对结果查询。
