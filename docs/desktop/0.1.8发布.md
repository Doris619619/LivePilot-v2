# LiveNest 0.1.8

## 用户变化

- 设备配置保留 1–5 步：添加 OBS、连接网页、检查 OBS、连接频道、准备素材。顶部步骤可定位当前实例；电脑配对只做一次。
- 每个 OBS 有独立控制、频道、素材状态。OBS 2 未配置不影响 OBS 1。路径和原始诊断收进技术报告。
- 配对表单按网页取码、粘贴连接分区。已连接时收为摘要；失败保留输入。
- 不影响开播的防火墙检查不再阻塞准备状态或作为客户故障弹出；真正的控制、授权、素材和未知操作问题仍就地说明。
- 托管 OBS 首次配置或主动修复时申请 Windows 授权，设置精确程序与 TCP 端口的非回环入站阻止规则。取消或策略拒绝只进入技术报告。
- Do 为客户；管理员必须明确具有 admin 角色且用户名以大写 U 开头。管理员网页可创建客户账号、设置初始密码、重置客户密码，不能创建或提权管理员。
- 下载页提供官方历史版本、日期、大小及下载入口；API 失败可重试或打开官方发行记录。

## 数据与部署

保留既有 OBS、配对、频道和素材。`scripts/migrate-account-roles.mjs` 须在备份后、服务停止时运行，先确认至少一个有效 U 管理员；只降级非 U 管理员并撤销其会话，密码摘要保持原值。管理员重置客户密码不会启用已禁用账号，也不删除配对或业务数据。

Problem v1 传输格式不变；展示与操作影响由共享策略判断。新增防火墙辅助程序随安装包交付，不安装提权常驻服务。普通启动和轮询不会请求 UAC。

- 单元回归：`problem-readiness`、`obs-firewall`、`obs-diagnostics`、`accounts-management`、`releases`，连同现有权限、上传、更新与迁移测试。
- `node scripts/desktop/readiness-acceptance.mjs`：五步导航、原实例定位、配对表单、双 OBS 独立状态、启动失败与恢复、技术报告折叠、键盘、780px/1280px。使用模拟桥接，未操作生产 OBS。
- `node scripts/preview/accounts-acceptance.mjs`：隔离数据创建/重置客户、客户被拒绝管理 API、历史版本列表、390px/1280px。
- 界面截图：[配对 1280px](screenshots/readiness/configuration-1280.png)、[双 OBS 780px](screenshots/readiness/two-obs-progress-780.png)、[客户账号](../screenshots/accounts-0.1.8/customers-1280.png)、[历史版本](../screenshots/accounts-0.1.8/history-390.png)。均明确标记模拟数据。
- 完整验证：`npm run verify` 通过 58 个测试文件、388 项测试、8 项部署脚本测试及类型/lint/网页/Agent 构建；`npm run desktop:build` 通过 Windows 安装包构建、资源和 fuses 检查。发布使用 CI 的正式安装包，不能将本地工作区构建冒充已发布版本。
- 实际 Windows 隔离 OBS：`scripts/desktop/managed-obs-acceptance.ts` 在独立目录、15455–15457 端口创建并验证三份 OBS。目录、密码、端口各自独立；添加后原实例场景和合成授权文件保持不变；未推流或录制，三个测试进程均安全关闭。未修改用户的两个现有实例。
- 原生 PowerShell 回归覆盖中文数据目录、8.3 短路径、DPAPI 解密和归属不匹配拒绝；规则命令为内存替身，不提权。Windows CI 运行 `scripts/desktop/firewall-smoke.ps1`，验证规则范围、重复执行、端口变更、自有规则清理；安装冒烟验证覆盖安装和数据保留。

## 验收边界

真实 OAuth、生产开播、跨机器 IPv4/IPv6 控制访问、组织策略受限环境、实际读屏播报及用户电脑自动更新重启须单独验收。浏览器模拟、规则字段检查和打包成功不等同于这些场景通过。正式发布、线上提交和安装包校验结果以 PR 发布记录为准。
