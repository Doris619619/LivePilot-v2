## 尚未执行或暂缓

- 没有 Node/Git/Docker 的独立干净 Windows 虚拟机验收。当前使用的是已有开发环境，另以不含这些工具的 PATH 启动安装程序验证运行依赖；不能等同于干净系统。
- Google 同意、视频上传/播放和完整开停播音画验收未执行；已完成真实网页配对、OBS 状态检查及音频上传隔离验收。实际频道授权和开播由用户主动完成。
- 两个不同安装版本的自动更新下载、延期重启和数据保留尚未实际验收。云端维护竞态单元测试通过不等于更新链路已实测。
- 不自动重新分配已经初始化的 OBS 端口；如被外部程序占用，应先处理占用。已配对后在 OBS 外部修改连接参数需恢复原值；首版的手动连接修正入口用于配对前。

## 实际安装后的路径兼容修复（0.1.0，后续发现跨上下文缺陷）

- 从 MSIX 宿主启动安装版时，Windows 可把 `%LOCALAPPDATA%` 文件操作重定向至包缓存；进程列表仍报告逻辑路径。原进程检查仅解析配置路径，导致已启动 OBS 被误判为未运行。
- 两侧统一解析真实路径后，实际进程与端口均识别为同一 PID。保留不同安装隔离和重复进程拒绝规则，增加别名、重复路径及不可访问进程回归检查。最终公开包包含此修复，不沿用早期本地包摘要。

2026-09-19 后续实测表明，上述“两侧解析真实路径”仍会在 MSIX 与普通桌面同时运行时认错另一份 OBS。此前同一上下文的验收不足以覆盖该情况；[本次修复与验证](OBS准备反馈修复.md)记录根因、用户恢复和内核路径方案。
