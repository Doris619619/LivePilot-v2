# LiveNest 桌面验证记录

日期：2026-09-19。目标：Windows x64，LiveNest 0.1.0。

## 已执行

- `npm run verify`：类型检查、Lint、143 项业务测试、8 项部署测试、网页生产构建、CLI Agent 构建通过。
- 维护测试覆盖开播与维护同时发生、OBS 推流/状态未知、快照过期、跨请求授权、实例 ID 保留、维护凭据隔离、邀请续期和禁止接管已配对设备。
- 本地登录测试覆盖未登录拒绝访问、输入验证和失败限流；真实 Electron 测试使用维护者提供的账号密码完成错误密码提示、登录、退出、重新登录。
- 真实 OBS 32.2.2 在临时独立目录初始化两个实例，通过认证、LIVE/VIDEO/MUSIC、全局音频检查，重复准备没有增加第三个实例，端口各不相同。测试未配对生产设备、未进行 OAuth、未推流。
- 桌面宽屏与 800 px 窄窗口截图检查通过，无横向溢出；离线帮助图片全部成功加载。
- 本地 NSIS 构建与包后检查通过：ASAR 内容、内置 Node 版本、OBS/Node 摘要、离线图片、Electron fuses。安装器约 379 MiB，确切大小和摘要以最终 `release/build-manifest.json` 为准。
- 已在当前用户默认安装目录执行 NSIS 安装，确认 `LiveNest.exe` 和安装标记存在；安装后能打开本地登录页面。
- 发现首次 Chromium 加密存储在测试强制退出后的恢复问题，改用直接 Windows CurrentUser DPAPI。跨独立进程解密与篡改拒绝测试通过；原空白测试密文仅备份，不覆盖生产数据。

## 最终安装包复验

- [x] 修订后的客户端重启保持双 OBS 配置：真实 Electron 验收输出 `obs: true, restart: true`，保留两个实例 ID、名称、端口及数据目录。
- [ ] 修订后的完整安装包重新安装并连续两次打开、登录、检查资源。

## 尚未执行或暂缓

- 没有 Node/Git/Docker 的独立干净 Windows 虚拟机验收。当前使用的是已有开发环境，另以不含这些工具的 PATH 启动安装程序验证运行依赖；不能等同于干净系统。
- 云端新增兼容接口未部署；线上此前核实为 `d182f4a843bf0fc9f91414da933b4e2bcf39ab16`，不能把本地代码当成已上线。
- 新安装身份的真实网页配对、Google 同意、素材上传和完整开停播音画验收未执行。原 Agent、OBS 和频道授权没有迁移或接管。
- 两个不同安装版本的自动更新下载、延期重启和数据保留尚未实际验收。云端维护竞态单元测试通过不等于更新链路已实测。
- 按用户选择，先交付本地安装器，`LIVENEST_RELEASE_TOKEN` 稍后配置；未进行公开发布，不宣称 CI 发布成功。
- 不自动重新分配已经初始化的 OBS 端口；如被外部程序占用，应先处理占用。已配对后在 OBS 外部修改连接参数需恢复原值；首版的手动连接修正入口用于配对前。
