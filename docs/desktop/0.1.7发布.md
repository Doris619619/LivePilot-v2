# LiveNest 0.1.7

“设备配置”和“本机 OBS”页面的每个已配置实例旁直接显示“启动并检查”，不再需要展开详情或手动寻找程序。点击只启动这个实例；已运行则检查现有进程，不新增实例、不改场景、不开始直播或录制。“重新检查”继续只读，不会启动程序。

所有 OBS 在“设备配置 → 配置所有 OBS”统一添加与配置。只有一个实例时明确显示“添加第二个 OBS”；名称、连接设置、失败候选和修复操作都留在此处。配对表单按步骤放在 OBS 准备之后，一台电脑只配对一次。频道和素材逐个显示所属 OBS，按钮打开网页原实例。“本机 OBS”专注日常启动和状态，配置按钮直接定位原实例。

结构参考：[Home Assistant 集中设置](https://www.home-assistant.io/integrations/config/)及 [OBS Profiles](https://obsproject.com/kb/profiles)。本产品管理独立 OBS 实例，不能把多个配置文件或场景集合当成多个独立进程。

启动阶段、成功和失败显示在对应实例旁。启动操作使用独立的 `launch-obs` 桌面命令，复用目标实例控制锁与现有启动器，避免与 Agent 对同一实例的操作并发。其他实例的直播不要求停止；目标端口被其他程序占用时保留错误，不结束占用进程。

控制连接与入站隔离是独立事实。即使尚未配对，控制已经响应时也显示最近本机检查结果；防火墙隔离待确认仍单独提醒，不再把它显示成控制尚未连接。旧本机检查标为“上次检查”，新鲜 Agent 快照优先按时间更新。

本次不自动调整用户 OBS 数量或数据位置，也不执行真实直播或 OAuth。回归、隔离界面截图、真实指定 OBS 启动与最终 Windows 安装包的验证结果记录在 PR。

实机验收另外发现 Windows 下仅探测 IPv4 可能漏掉已有 OBS 的 IPv6/通配监听。新增和修复实例现在同时核对实际监听表与双栈端口，避开其他 OBS 已使用的端口；不会结束原进程，也不会擅自更改现有实例端口。

本地验证：53 个文件、371 项单元测试及 8 项部署脚本检查通过，完整 verify 与桌面编译通过。浏览器验证第二个 OBS 的新增入口、目标页面定位、键盘与 780/1280px 布局。真实隔离双 OBS 使用 4456/4457，界面启动第一套、第二套 PID 不变，重复点击复用进程。认证为模拟服务，未进行生产配对、OAuth 或开播。

待配置 OBS 尚未处理完时暂停新增，明确引导重试原候选或撤销，避免误建更多实例。浏览器已覆盖该禁用与引导。
