# LiveNest 0.1.3

## 版本与范围

本版从已合并的客户故障恢复代码 `c3f68f9` 准备，版本提交另经 PR 合并后，以最终 main 提交创建 `v0.1.3`。原 `v0.1.2` 指向 `0da5dad`，其发布流程已取消，不能移动该标签来承载新代码。

- 包含客户账号与设备归属、管理员网页入口的兼容客户端。
- 安装时分别选择程序和数据位置；既有数据、身份、OBS 与频道绑定保留。
- 创建独立 OBS，区分程序未启动、控制端口未监听、认证失败及端口冲突。
- 故障绑定原实例与原操作，区分结果未知、失败、取消和保存失败；提供检查、设置步骤、原目标重试和脱敏摘要。
- 数据迁移分别反馈复制、切换和重连；更新分别反馈检查、下载、校验和安装准备。

## 发布与兼容

Windows CI 对稳定版本标签执行完整 `verify`、桌面构建、包后检查，上传草稿并回下载逐字节核对，最后发布至 [LiveNest-Releases](https://github.com/Doris619619/LiveNest-Releases/releases)。安装器、blockmap 与 `latest.yml` 必须来自同一次构建；源码工作流保留含提交与 SHA-256 的 `build-manifest.json`。

新 Agent 只在云端声明 `problem-v1` 后发送新增字段；旧云端继续接收原格式。客户端发布不等于云端或网站已部署。现有网站 `/download` 的静态 0.1.1 入口独立管理，本次最新安装版及客户端更新源使用公开 GitHub Release。网页故障交互需要后续部署云端版本。

下载与安装均由用户主动执行；重启更新需确认空闲和维护许可，不自动停止直播。已有实例的 OBS 不随客户端升级而替换。

## 验证与边界

发布门槛为本次完整 `npm run verify`、最新 PR 与 main 的 Windows / Ubuntu 检查、Windows 发布工作流、产物冒烟检查和公开资产回下载校验。具体运行结果和最终发布提交记录在本版本 PR 与 GitHub Actions 中。

2026-09-23 本地预检已通过：完整 `verify`（48 个测试文件、329 项回归、8 项部署测试、类型检查、lint、网页与 Agent 构建），桌面编译和静态构建；隔离真实 Electron 的 0.1.3 版本、启动、未登录 IPC 拦截、Renderer Node 隔离、离线帮助及 780px 布局；模拟故障脚本的原目标、只读恢复、折叠摘要、上传查询、失败表单保留、键盘与 390/780px 界面。测试输出保存在忽略的 `.data/release-preflight`，未写入用户配置。

故障回归覆盖及明确标为“模拟故障”的界面证据见[客户报错改造验收](../客户报错改造验收.md)。本次不以真实 OAuth、生产直播或真实用户数据迁移作为自动测试；干净 Windows 安装与两个真实安装版本之间的升级仍须单独验收。

当前未配置 Authenticode 证书，安装器签名状态须以发布后实测为准；不能把构建器的 signing 日志当作可信发布者签名。
