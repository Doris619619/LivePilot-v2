# OBS 启动反馈

本次修改针对已配置 OBS 的“启动并检查”，尚未发布安装器。原实现把启动与控制确认合成静态等待文案，内部重试时间与对用户的等待承诺不一致；成功后仍显示启动主按钮，动作又与说明分离，容易造成“卡住后突然完成”和重复点击的误解。

## 展示与操作

| 实际状态 | 界面反馈 | 就近操作 |
| --- | --- | --- |
| 未运行 | OBS 尚未启动 | 启动并检查、重新检查 |
| 检查／启动进程 | 正在检查并启动 OBS | 连接帮助 |
| 已检测到进程 | 正在连接控制服务 | 连接帮助 |
| 控制服务已回应 | 正在确认 OBS 状态 | 连接帮助 |
| 已等待至少 30 秒且观测仍新鲜 | 连接等待较久，检查仍在继续 | 连接帮助 |
| 20 秒没有实际检查结果、读取失败或宿主尚未返回到期结果 | 检查结果暂未更新，不声称任务仍正常进行 | 重新读取状态、连接帮助 |
| 本轮达到 60 秒 | 本轮连接检查已超时，OBS 可能仍在运行 | 重新检查、连接帮助 |
| 新观测确认超时后已连接 | 控制连接已恢复，并说明上次检查超时 | 重新检查 |
| 正常完成 | 状态与确认时刻合成信息组；复查与次要详情同行，明细默认收起 | 重新检查、查看详情 |

正常连接时状态与复查按钮同行；其他状态的动作紧邻状态下方，成功态没有蓝色启动按钮或远离说明的重复完成徽章。步骤折叠时保留完成状态，展开后由具体结果说明。等待时间显示为“已等待”，不伪造剩余时间或百分比。阶段使用状态语义，秒数不每秒播报；支持减少动态效果和小窗口换行。

正常连接采用用户选定的方案 3：状态徽记与两行文案组成信息组，描边复查按钮和浅灰次要详情按钮同行。确认时刻直接显示为 `HH:mm`，不每秒跳动。详情默认收起，展开后以键值行显示当前观测的连接状态、配置端口、完整确认时刻，以及实际存在的“启动检查用时”。该耗时属于保存的启动轮次，不等同于刚刚复查的耗时。没有认证或延迟观测时不添加对应结论。

详情由原生按钮控制唯一关联区域，使用 `aria-expanded`、`aria-controls` 和 `hidden`，保留 Enter / 空格及可见焦点。成功模式切换后默认收起，即使等待时曾展开；成功明细不再显示旧阶段观测或已结束的 60 秒等待说明。窄窗口下信息组在首行，两个操作在第二行。

“重新检查”在原按钮内反馈：请求中显示“正在检查…”并禁用，结束后显示 4 秒“检查完成”，随后恢复操作名称；失败时保留原因与重试入口，不额外显示独立的完成标签。设备配置与本机 OBS 共享指定实例的检查状态。即使控制连接与点击前一致，也能辨认操作已结束；检查完成仅表示请求执行结束，连接结论仍依据最新观测。按钮的无障碍名称包含可见状态，状态播报带实例名称。正式客户端不延长请求耗时。

进行中的真实阶段与已等待时间，以及慢等待、结果陈旧、超时故障、恢复说明继续直接呈现，不放入折叠详情。进行中和未恢复的失败详情保留阶段观测、60 秒预算与“不关闭 OBS、不自动开播”的操作边界。

30 秒、20 秒及 60 秒是本产品的策略值，不是设计系统规定的通用阈值。今后应结合真实设备耗时分布调整。

## 实现边界

- 桌面专用执行器使用统一 60 秒预算，覆盖进程检查、启动、控制连接及三次只读确认。没有新增开播、场景写入或 OAuth 操作；仍使用目标实例的控制锁。
- 宿主报告阶段、截止时间、真实检查时间和检查次数。渲染时钟只计算耗时，不充当执行器心跳。到期取消进程查询，阻止迟到结果继续发起请求、启动进程或覆盖终态。
- 每个实例保留最近一轮启动记录，复查或切换页面不会抹掉超时事实。记录只在本次桌面进程内保留；退出客户端后不保留操作历史。
- 当前状态来自该实例最新的新鲜观测。只有晚于失败终点的成功观测才能显示恢复；旧成功、其他实例成功或陈旧快照都不能清除本轮故障。
- 状态 IPC 读取超过 10 秒会释放读取入口，允许重新读取；迟到的旧请求不再提交状态。启动仍沿用宿主全局忙碌约束，不改变跨实例并行模型。
- 超时断开本轮检查连接，不强杀 OBS；底层异步返回由守卫隔离。防火墙检查仍独立在后台进行，不再为重复控制连接延长启动等待。

## 设计依据

- [Fluent Progress bar](https://fluent2.microsoft.design/components/web/react/core/progressbar/usage)：未知耗时采用不确定进度与具体说明。
- [Carbon Inline loading](https://www.carbondesignsystem.com/building-blocks/core/components/inline-loading/guidelines)：在操作附近连续反馈等待与结果。
- [WCAG 状态消息](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)：让辅助技术感知状态，同时避免频繁播报。

本实现借鉴这些原则，具体阶段、超时契约和按钮层级来自当前 OBS 流程的实际约束。
