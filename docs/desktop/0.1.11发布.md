# LiveNest 0.1.11

发布视频可独立绑定多个账号，在本机准备素材包后通过网页检测、设置时间、日历确认和自动执行。“我的发布”按频道展示多个发布包的真实公开进度、剩余与异常，历史支持搜索、筛选和单条详情。确认后返回第二步可调整未完成任务的时间，保留原上传会话、最终文件和视频关联。

本版包含 PR #26 的 PublishingRunner、上传断点和重启恢复，以及已合并 PR #25 的开播详情配置；新网页场次和新版 Agent 的直播可见性缺省为公开。测试直播须主动选择私密或不公开。

## 审计与验证

合并前独立审计发现并修复取消/公开竞态、旧取消覆盖最新意图、连续改期中间时刻提前释放、清理或设备转让后迟到数据写回，以及 Windows 迁移损失文件时间精度。新增故障回归及真实临时 NTFS 文件验证，不操作客户素材、OBS、授权或直播。

依赖审查发现 Next.js 16.3.3 的 [ImageResponse 安全公告](https://github.com/vercel/next.js/security/advisories/GHSA-vcvr-r3jv-pc5j)，仓库未使用该入口，仍将 Next/env/eslint/SWC 同版本升级至修复版16.3.6；开发链 [brace-expansion](https://github.com/juliangruber/brace-expansion/security/advisories/GHSA-q2hr-2g5m-vwhr) 按原版本范围升级至1.1.21/5.0.12。生产与完整 `npm audit` 均为0项，没有跨大版本或强制更新。Windows原生迁移集成测试使用20秒有界等待，退出后才清理合成文件；不改变业务断言或全局门槛。

- 本地完整 `npm run verify`：76 文件 / 629 测试、8项部署检查、类型、lint、Next.js及Agent构建通过。首次旧 OBS 修复测试临时 rename EPERM，独立及完整重跑通过；断言和门槛保持。
- 发布页面生产构建的模拟浏览器验收覆盖100包、4步、独立账号、日历、确认后改期和四种宽度；不是实际频道验收。
- 当前提交 Windows/Linux CI、Windows 安装器与正式标签发布结果在 PR #26 的验证节更新；未完成的门槛不能写成通过。

## 升级与发布顺序

保留原设备身份、直播授权、OBS、素材和恢复检查点。先部署含审计修复的兼容云端，暂保留0.1.10网站下载；源码0.1.11稳定标签的Windows CI通过真实安装、同版覆盖、保留数据卸载及草稿上传后的逐字节回下载校验，才公开安装器与更新元数据。随后核对安装器和构建清单，同步网站静态下载及最终合并版本。公开资产不覆盖旧版，程序回退不覆盖新的业务数据。

## 尚待真实验收

独立账号 OAuth、真实 YouTube 上传/跨进程续传、未知末块、Unicode与项目Audit、Agent离线后自动公开、真实FFmpeg音乐合成、跨多日滚动，以及客户0.1.10到0.1.11的数据升级仍待授权验收。CI同版覆盖不能替代客户旧版升级。自动发布开关和公开验收标记默认关闭，只有完成真实能力验收后才应开启；API项目限制不会由客户端升级自动解除。

公开下载以 [GitHub 发行页](https://github.com/Doris619619/LiveNest-Releases/releases/tag/v0.1.11) 为准，合并、云端切换、安装器公开是三个分别核对的结果。
