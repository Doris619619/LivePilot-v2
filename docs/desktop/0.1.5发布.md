# LiveNest 0.1.5：安装器空白报错修复

## 根因

0.1.4 的正式 NSIS 安装器以插件目录为工作目录，Windows x64 下启动的 PowerShell 在 `Add-Type` 编译路径辅助函数时，将同目录原生插件 `System.dll` 当作 .NET 引用，报程序集格式错误。初始化发生在异常捕获之前，未生成结果 INI，安装器直接展示空白错误框。该错误与客户选取 D 盘或配对状态无关。

最小 NSIS 程序复用了正式版本的插件目录、文件系统重定向模式和校验命令。修复前退出码 1、无结果文件；修复后退出码 0、正确读取已有目录。仅从命令行运行脚本或解包安装文件会漏掉这一问题。

## 修复

- 在载入程序集前，将进程工作目录固定为 PowerShell 自身目录，避免插件目录 DLL 干扰；初始化纳入结果文件错误处理。
- 安装器在读取、校验、保存三个阶段均提供非空兜底原因和返回码。
- 原数据位置校验、身份保护与运行中客户端拦截继续保留，不通过删除配置或跳过校验强行安装。
- 发布流程在上传公开资产前实际运行 NSIS 新安装、静默覆盖升级、保留数据卸载；使用一次性 GitHub Windows 用户、中文空格路径和合成数据。脚本拒绝在普通本机或已有安装记录的用户下运行。

## 验证记录

- 原生 NSIS 故障复现与修复后只读校验通过。
- Windows 回归在含冲突 `System.dll` 的工作目录运行真实 PowerShell，覆盖读取、校验、保存及失败保留旧定位记录。
- 完整 verify、打包、正式发布 CI 和真实客户覆盖升级的最终结果记录于本次 PR；未完成前不视为通过。
- 不包含实际直播、OAuth 同意或用户数据迁移测试。
