# LiveNest 0.1.12

**状态：发布准备，尚未核对正式交付。** 本版来自 [PR #28](https://github.com/Doris619619/LivePilot-v2/pull/28)。源码合并、Cloud 部署、稳定标签 CI、公开安装器及网站静态下载分别待核对；版本号变更不代表已发布。2026-10-06 发布准备时，公开最新安装版仍为 0.1.11，以 [公开发行页](https://github.com/Doris619619/LiveNest-Releases/releases/latest) 为准。

## 用户可见变化

准备素材时直接显示目标电脑的真实 Inbox 路径；时区支持搜索，执行页展示视频处理阶段，改期后区分新计划和 Agent 远端确认。网页可切换本浏览器已登录成员，旧标签页不能借用切换后的身份操作。移除发布产品开关，继续保留合规同意、频道和权限保护，Google API 项目限制仍生效。

内置 Agent 按 UTC 秒核对 YouTube `publishAt`，修复同秒整秒回读被误报为排期失败；旧检查点保留，恢复仍要求明确核对、当前任务修订和完整远端证据。已公开的视频确认公开事实，不重新上传，不覆盖人工排期。行为细节及模拟验收见 [发布工作台易用性修复](../发布工作台易用性修复.md)。

## 兼容与升级

网页行为由 Cloud 更新提供；排期精度与恢复修复需要客户安装 0.1.12 内置 Agent，单独部署网页不能替代升级。保持现有设备身份、频道授权、OBS、素材目录、上传会话及 videoId，无数据库或源视频迁移。

客户端更新继续使用已有安全退出和安装链：直播、录制、状态未知或任务排空失败时不强行重启。需要手动覆盖安装时，等待任务完成并通过托盘正常退出，沿用原数据位置；不卸载或删除客户数据来获取新版。实际 0.1.11 → 0.1.12 客户升级仍需验收。

## 正式发布顺序

1. 最终版本提交重新执行 `npm run verify`，核对当前 PR 的 Linux、Windows 与安装器 CI；合并后记录确切提交。
2. 在隔离 Linux release 目录构建并验证最终 Cloud，暂不切换当前页面。根版本同步为 0.1.12 后，下载页会直接使用 `/downloads/0.1.12/`，资产就绪前不能让该页面成为当前版本。
3. 从经验证的合并提交创建稳定标签 `v0.1.12`；源码仓库的 `desktop-release.yml` 运行完整 verify、防火墙辅助验证、桌面和真实安装器 smoke，随后草稿上传、回下载逐字节比较，匹配后才公开到独立仓库 `Doris619619/LiveNest-Releases`。
4. 从指定成功的标签 run 下载 `livenest-windows` artifact，保留原始 `build-manifest.json`；另取公开 Release 的完整 REST JSON，下载 exe、blockmap 和 `latest.yml`。核对版本 0.1.12、最终提交、clean/release、大小、CI SHA-256、GitHub digest，以及更新元数据的 SHA-512。失败 run 也可能上传 artifact，不能凭文件存在认定发布成功。
5. 将已验证的同版资产与 CI 清单同步到新的网站静态目录；禁止覆盖已公开版本。核对静态下载后再切换最终 Cloud，保留原代码与失败记录，回退不恢复旧业务数据，也不撤销 YouTube 排期。
6. 匿名检查网页、鉴权和安装器下载，核对 HEAD、Range、安装器 `MZ`、构建清单与版本；需要保留既有直播时，切换前确认稳定状态，启动后要求新的当前心跳、快照及原直播关联。

版本一致的稳定标签和源码 CI 为正式发行入口；本地 `desktop:build` 或 PR 安装器 CI 不能冒充正式发行。构建清单仅随 Actions artifact 提供，公开仓库只上传安装器、blockmap、`latest.yml`；网站清单需独立同步。跨仓库发布凭据仅由 Actions Secret 注入，不进入源码、客户端或日志。已有 0.1.11 部署助手中的固定版本和路径必须重新审查，不能原样用于 0.1.12。
