# 异地网页控制与素材上传

## 两台电脑如何分工

A 只用浏览器；B 在日本运行一个常驻 LivePilot-v2 服务、多个 Portable OBS 和本地素材库。成员可以在日本或深圳登录操作。OBS 始终直接向 YouTube 推流，网页与公网入口不转发直播视频流。

本次完成代码及隔离本地验收，没有配置 AWS、域名或公网隧道。B 必须保持开机、联网及可用的 Windows 用户桌面；不要把需要桌面环境的 OBS 放进非交互式 Windows 服务会话。网页断线不会停止 B 上已经开始的直播。

## 成员登录

在 B 的项目目录运行：

```powershell
npm run member -- create alice
npm run member -- create bob
npm run member -- list
npm run member -- reset alice
npm run member -- disable bob
```

create/reset 交互式读取两次密码，不回显，不接受命令行明文密码。账号为 3–32 位小写字母、数字或下划线；密码为 12–256 个字符。没有默认密码、公开注册或邮件依赖。账号禁用或密码重置立即撤销该账号所有会话。

成员平等管理全部 OBS 与频道；工作台登录账号与 YouTube 授权账号独立。每个 OBS 继续绑定一个不同频道。成员可以共同操作既有频道，不需要每人重新授权 YouTube。

会话默认 12 小时，使用 HttpOnly、SameSite=Lax Cookie，HTTPS 下启用 Secure。服务端只保存 token 摘要，每次业务请求重新校验会话与账号版本。登录按账号及整个入口限速；不信任任意转发 IP 来绕过限速。未登录不能读取素材、实例或直播状态。

账号和审计默认在 `.data/access`；其他实例数据仍在原位置。账号操作共享短锁，竞争时显示忙碌，可稍后重试。请将账号目录和加密授权一起纳入 B 的受保护备份，切勿上传到 Git。

## 素材操作

已有 B 上的素材可以直接在对应 OBS 面板选择。A 上的文件通过顶部“上传这台电脑的素材”上传：

1. 选择目标实例的素材库、视频或音乐、当前电脑文件。
2. 浏览器逐片计算完整文件身份，再以 8 MiB 分片顺序上传。
3. 进度只显示 B 已确认落盘的字节。断网后重新登录、刷新并选择同一文件可继续。
4. 传输完成后 B 重新核验文件；只有通过校验才加入素材库，所有面板刷新列表。
5. 完成不会自动更换直播素材。先选择已上传文件，再显式开始直播。

默认单文件上限 20 GiB，可用 `LIVEPILOT_UPLOAD_MAX_BYTES` 调整。客户端每个页面提供一个上传入口；每个上传顺序发送分片。多个成员或标签页可以上传不同文件，服务端按上传记录互斥，并在媒体库级别预留剩余容量，额外保留 512 MiB 可用磁盘空间。后台其他程序仍可能耗尽磁盘，分片写入时会再次检查并暂停。

刷新后恢复依赖浏览器保留的非秘密上传标识；清除网站数据、改用另一台操作电脑或另一账号后需要重新上传。一个上传的续传绑定创建成员与实例，完成后的素材由共享同一媒体库的实例共同使用。

临时内容保存在媒体库 `.uploads/<上传 ID>`。7 天没有收到新分片即过期；创建新上传时清理过期临时文件。过期目录若仍被占用则跳过，后续创建上传再次尝试。取消仅删除自有临时数据，完成文件长期保留。第一版没有网页删除素材功能。

同名文件添加唯一后缀，绝不覆盖已有文件。完成时同一磁盘以不覆盖的硬链接原子发布，随后移除临时入口；媒体磁盘必须支持硬链接（建议 Windows 本地 NTFS）。不支持时明确报错，未完成数据保留供核对。文件扩展名允许范围沿用原版；上传校验不代表 OBS 必定能解码，真实播放仍需验收。

B 校验期间网页可关闭。校验异常会显示安全错误，可以重试完成校验；若文件身份不符，应取消后重新上传。

## 开停播与恢复

`POST /api/control` 新增 UUID 格式的 `requestId`，原有 `instanceId` 和 action/媒体字段保留。受理记录持久化后返回 HTTP 202：

```json
{"operation":{"id":"请求 UUID","action":"start","actor":"alice","status":"accepted","updatedAt":"ISO 时间"}}
```

202 表示已受理，不代表直播成功。Next.js 的 after 在 B 的常驻 Node 进程内继续执行；`/api/status?instanceId=...` 返回当前 operation，包括 accepted、running、succeeded、failed、interrupted，以及实际 OBS/YouTube 状态。不得部署为有短执行时限或自动休眠的 serverless 函数。

同一请求标识和输入不会重复执行；同一 OBS 的冲突命令及 OAuth 操作互斥，不同 OBS 各自执行。客户端保留结果未知的请求标识，核对后才开始新操作。操作者与结果记录到 `.data/access/audit`；不写请求全文、密码、Token 或推流密钥。

页面断线不取消命令。B 服务重启时，旧进程未完成命令标记 interrupted，不自动重放。页面继续读取真实 OBS/YouTube 状态；保留已创建场次的恢复记录。若留下互斥锁，先确认旧服务已经停止，再在 B 上恢复：

```powershell
npm run recover:lock -- main control
npm run recover:lock -- main commands
npm run recover:lock -- main access
npm run recover:lock -- main uploads
npm run recover:lock -- main upload <上传-ID>
```

命令只删除所属目录中、记录 PID 已不存在的指定锁；不重置直播状态或授权。服务/上传被强制结束后，需要恢复相应锁再重试。存在无法确认的 PID 或目录链接时停止处理，要求人工核对。

结束顺序保留：YouTube 确认 complete 后才停止 OBS；拒绝停止不属于本应用的推流。YouTube 授权事务额外绑定发起成员；会话失效或更换成员后要重新发起授权。

## 公网入口配置契约

开发模式继续 `http://127.0.0.1:3010`。未来部署到公网：

- 为 B 提供固定 HTTPS 地址，例如 `https://live.example.com`，设置为 `LIVEPILOT_ORIGIN`，不带末尾斜杠或路径。
- Google Web OAuth 客户端添加 `https://live.example.com/api/youtube/callback`。不能只改首页地址或沿用不匹配的本机回调。
- 入口通过专用连接转发到 B 的 `127.0.0.1:3010`，保留配置的公网 Host、Origin、Cookie 和原始 URL。应用不依据任意 X-Forwarded-Host 推断身份。
- 允许至少 8 MiB 请求体并流式转发上传；禁止缓存页面和业务 API。公网入口不转发 OBS 的 4455 等端口。
- B 上使用 `npm run build`、`npm run start` 常驻运行，不能同时运行 dev 与 start。服务启动脚本继续只监听 loopback。
- AWS、隧道或反向代理的最终选择、域名购买和日本/深圳线路实测属于后续部署工作。

可选 `LIVEPILOT_DATA_ROOT` 改变整体运行数据位置，`LIVEPILOT_ACCESS_DIR` 单独指定成员目录；默认不变。不要为升级而改数据位置或加密密钥。运行数据和环境密钥从构建追踪中排除。

## 验收证据

自动测试覆盖登录撤销与过期、匿名业务访问、HTTPS Cookie、伪造 Host、成员 OAuth 隔离、命令去重和重启、上传中断/损坏/续传、重名无覆盖、磁盘预留与过期清理，以及原有多实例开停播规则。

`scripts/remote-smoke.mjs` 启动隔离生产服务和本机 HTTPS 反向代理，使用临时账号、临时数据目录和测试文件。需要本地可用的 Playwright/Chromium 和 OpenSSL；可通过 `LIVEPILOT_PLAYWRIGHT_MODULE` 指定 Playwright 的绝对 index.mjs 路径，通过 `LIVEPILOT_OPENSSL` 指定 OpenSSL。先构建，再执行脚本。测试证书仅在临时目录，不安装到系统。

已验证真实浏览器登录、两个面板、9 MiB 文件断网后刷新续传及最终 SHA-256 一致、上传完成刷新素材、页面关闭后命令保存结果、重复请求、跨站拒绝、退出撤销，以及 390/768/1440px 布局。模拟 OBS 路径为空，控制命令以安全失败结束；这些结果不等同于真实推流验收。
