# YouTube 配额保护与管理员数据台

本次实现针对 [配额消耗审计](YouTube_API配额异常消耗审计报告.md) 已证实的停播查询、短流重连和缺少调用计量问题。源码提供保护机制与管理员界面，**此文不代表生产已部署、安装版已升级或真实直播验收通过**。

## 使用入口与数据口径

管理员总览新增“YouTube 配额”页签：查看本应用预扣预算、准入预留、实际发起的调用次数、方法与设备排行、分钟趋势、日志完整性和设备保护协议覆盖率。点击分钟趋势可以下钻，按 PT 配额日、UTC 时间范围、设备、实例、方法、来源和结果筛选；可导出 CSV / JSONL。导出会处理 CSV 公式注入，不包含令牌、密钥、请求地址或聊天正文。

界面布局依据 [成熟数据台设计调研](YouTube数据台设计依据.md) 实施。数据台仅每 15 秒读取 Cloud 已保存的数据，隐藏、离页、卸载时停止轮询。查看、筛选和导出不会为了刷新界面而查询 YouTube。普通客户没有管理员日志权限，只获得自己设备的暂停原因、下次核对时间及平台收尾状态。

必须区分三种事实：

- **准入及预扣**：Cloud 同意一次请求并预先占用预算，可能随后尚未发送或进程就退出。
- **发起与结果**：Agent 即将发送时记 start，结束时记 finish；缓存命中、预算拒绝不计实际上游尝试。
- **Google 实际用量**：本应用无法直接获得整个项目所有消费者的账单；显示的是按官方成本预计 units 和应用预算，不是假定的 Google 真实余额。失败/超时也不等于免费，未知结果不自动退款。

成本目录版本为 2026-10-15，依据 [官方配额表](https://developers.google.com/youtube/data/determine_quota_cost)。聊天 streamList 每次连接 5 units，insert 每次 20；连接内多个批次不重复计连接。视频上传初始化使用独立上传桶，分片/探测记录传输事实，不重复计成视频上传调用，也不宣称其独立计费已获核实。OAuth token / revoke 记录安全网络事件，不占 Data API 通用桶。

## 默认保护与接入

| 项目 | 默认值 |
| --- | --- |
| 官方通用额度配置 | 10,000 units/day |
| 本应用通用日预算 | 9,000，策略最多使用所配置官方额度的 90% |
| 直播控制预留 | 上述总预算内 500，仅已验证控制任务可用 |
| 自动回复发送子预算 | 全项目 2,000/day，按成本最多约 100 次发送尝试 |
| 聊天室建连子预算 | 500/day |
| 后台平台查询子预算 | 2,000/day |
| 发布 | 沿用原发布更严格的子上限，同时受总预算约束 |
| 自动化速率 | 30 units/minute，突发 60 units |
| 上传 / 搜索 | 独立计数桶，各按已配置与官方默认限制 |

子预算是上限，不是多份可叠加额度。管理员调整策略仍受项目总账约束，不能更换项目字符串绕过预算。真实项目默认映射 Cloud 已配置的 Google client；额外 client 只允许由服务端明确映射到同一项目。配置 `LIVEPILOT_YOUTUBE_CLIENT_PROJECTS` 为 client ID SHA-256 指纹到 `current-project` 的 JSON 映射；不同 client 的哈希不代表不同 Google 项目。映射不可放入浏览器或日志来代替权限校验。

**首次接入当日不会从零假账自动放行。**原发布账本已用额度和未消费预留先迁移；管理员填写当前 PT 日的接入前用量基线，或等待下一 PT 配额日后开启自动化。接入后的消费继续累计，重复输入不会清空账本。历史未知时界面明确标注，不能把昨天缺失的日志伪装成零。

Cloud 用 fsync 后的原子文件与短事务预扣，attemptId 幂等。热账本只保留当前 PT 日明细，旧日准入凭据按日独立归档 14 天；日汇总保留 90 天。热账本与未完成结果预留总计达到 32 MiB 时拒绝新增准入，零通用成本的上传传输也受容量约束，不删除当天幂等记录腾空间。准入响应丢失时重发同一个 Cloud 请求不会重复扣账；重新请求 Google 必须产生新 attemptId。发布任务预留与实际消费共用总账，旧发布收费路由兼容，新的 Agent 不再同时走旧收费路径。

新 Agent 需要 `youtube-quota-v1` 和 `youtube-usage-v1` 两项能力。Cloud 断线、旧 Cloud 不支持保护、项目未映射、预算账本不可读时，新的 Google 请求关闭；本地 OBS 观察、既有推流和已授权的本地停止保留。CLI 与桌面共用同一运行流程。未接入预算控制端的独立本地服务不会默认绕过保护发出 Google 请求。

明确 quotaExceeded / dailyLimitExceeded 会先在 Agent 关闭 Data API 入口，再通过 Cloud 传播全项目熔断，等 PT 午夜重置；OAuth 撤销不受无关 Data API 日额度阻断。普通网络错误、429 和通用 gRPC code 8 不冒充每日额度耗尽。非平台日额度的等待最多一分钟重新检查 Cloud，便于管理员补基线、改策略后恢复，**重新检查预算本身不请求 Google**。

## 修复后的运行行为

### 状态查询与重连

- 停播、空闲、已确认 complete，以及已发起停止但平台待收尾的实例不再周期读取场次和推流对象。
- 频道名称等元数据缓存 24 小时；本地 OBS 状态采样继续独立运行。
- 健康平台检查至少间隔 5 分钟，并根据剩余后台预算、活跃实例数及距 PT 午夜的时间公平拉长间隔。低额度、多实例时显示最后真实核对时间，不能将旧平台状态冒充实时确认。
- 相同凭据重连不清平台缓存。AI 环境变化取消旧生成，但不冒充 OAuth 变化触发额外平台查询。
- 空批次不再清零连接失败计数。连接稳定 120 秒后才重置退避；不稳定连接按 1/2/4/8/16/30/60 秒退避并加抖动，连续五次冷却 15 分钟，且每次建连均受项目预算限制。
- 分页统一限制 20 页、总计 30 秒并检查重复 token；越界表示未确认，不能据此重复创建场次或视频。

### 停止与平台收尾

结束操作先保存停止意图并取消聊天，再核对 OBS 归属、停止本应用所属推流并确认。Google 不可用时也不能阻止这部分。

平台尚未确认结束时保留原 broadcastId / streamId 和 `platformClosePending`，显示“OBS 已停止；YouTube 场次待结束”。下一场开播被阻止；用户恢复连接后只对原场次进行收尾，不能创建第二场。外部 OBS 推流仍由 OBS_FOREIGN 保护，程序不会为了测试而停止它。

桌面实例增加“停止本机推流”入口，通过受信窗口和固定 child IPC 执行，不访问 Cloud 或 Google。只有本次有效客户登录已核实当前精确设备绑定时可离线使用；退出、过期、重新登录、解绑、凭据变化或明确权限拒绝都会清除许可。这一例外不授予离线开播、配置修改或换号权限。

## 日志保存与故障行为

真实请求开始、结束不采样。高频缓存/阻断决定按分钟合并计数，避免日志形成新的请求或写盘风暴。事件只包含白名单方法、来源、关联操作 ID、耗时、结果、恢复时间、连接批次数量及业务重试次数等元数据。业务重试次数来自聊天连接和发布任务的真实恢复次数；同一个准入 ID 的 Cloud 传输重试不计成另一次 Google 尝试。

- Agent 明细保留 7 天，硬上限 128 MiB；每分钟本地维护独立于 Cloud，离线期间也执行轮转；Cloud 明细保留 14 天，硬上限 512 MiB；日汇总保留 90 天。
- Agent 分段、批量补传，Cloud 持久确认后才移出待发送队列，已确认明细仍本地保留至轮转期限。
- eventId 与 bootId/sequence 去重；丢失确认、重启和重复提交不能重复累计。
- 超过容量、日志写失败等情况必须显示缺口与最后同步时间。日志故障不阻塞心跳、本地停止和已有推流；关键预算持久化失败则拒绝新的 Google 请求。
- 明细绝不保存 access/refresh token、OAuth code、client secret、OBS 密码、Stream Key、上传 session URI、完整 URL、原始异常、请求体或聊天文本。

## 接口与权限

Agent 通过已有设备身份与有效 session 访问：

- `POST /api/agent/youtube-quota/admit`：方法、来源和关联身份；Cloud 决定成本与是否放行。
- `POST /api/agent/youtube-quota/result`：固定结果分类，明确 quota 尽快传播。
- `POST /api/agent/youtube-usage`：最多 64 条安全事件，返回精确确认 ID。

管理员接口为 `/api/admin/youtube-usage` 及其 `events`、`export`、`policy` 子路由。所有接口校验角色、设备和独立发布账号归属，禁止缓存；客户端传来的设备 ID 不替代认证身份。记录策略修改的操作者，但不记录敏感配置。查看与导出日志不转发成真实 YouTube 请求。

## 验证与部署边界

验证使用合成凭据、Mock Cloud / Google、假时钟和隔离临时目录。覆盖预算争抢、失去响应、子预算、短时限流、quota 传播、跨 PT 日与 DST、损坏账本、日志轮转/补传、权限与脱敏。

本轮浏览器验证直接挂载真实管理员组件：每 15 秒读取、隐藏/恢复、分钟下钻、筛选、策略保存、实际 CSV 下载、离页卸载、桌面与 390px 布局。截图为**模拟数据**，不是生产控制台用量。

本轮 `npm run verify` 通过：129 个测试文件、1,262 项单元/回归测试，8 项部署脚本测试，TypeScript、ESLint、Next.js 生产构建及 Agent 构建均通过。另通过桌面主进程/worker 编译和桌面 renderer 静态生产构建。管理员真实组件浏览器回归 14 个场景通过，外部请求为零；包括当天较早小时选择与分钟下钻。自动化通过不等于真实开播、OAuth 同意、观众播放流畅或实际聊天发送验收。

部署顺序为 Cloud → Agent。旧 Agent 自主后台请求无法仅靠新 Cloud 阻止，必须在数据台看到保护覆盖率完整后，才能声称这些设备都纳入保护。真实发布安装器、升级运行中的客户机、开停播和发送消息应按原授权流程另行验证。此实现不接入 Google Cloud Monitoring 历史数据，也无法恢复此前未记录的请求明细。
