# 直播 AI 观众互动

## 使用（Cloud 0.1.17 已部署，新能力需要配套 Agent）

在「直播编排」编辑本场 AI 观众互动：自动回复开关、人设、补充描述（最多 2000 字符）和发送间隔（5–60 秒，默认 5 秒）。互动参数纳入直播配置包；前面的输入与完整配置读写同一份 Selection，开播时 Agent 按这份参数执行。旧包没有互动字段时保留本场参数，不批量改写旧数据。

网页互动区整理（当前分支，尚未部署）：自动回复开启时直接编辑人设和接话方式；更多参数与风格示例按需展开。「试聊」默认收起，展开后可输入留言或选取例句，点击「生成回复」才调用模型。关闭自动回复仍可展开试聊并选择人设，不会因此启用本场自动回复。试聊输入与结果在本页折叠后保留，空状态不显示结果列表或比较说明。该展示方式仅用于网页直播编排，其他设置入口保持原有展示与保存语义。

回复跟随当前观众留言的语言，以当前频道发送，格式为 `@观众称呼 回复内容`，不添加 `[AI]`。模型仍不得冒充真人或声称执行直播控制。儿童内容或关闭聊天的场次可能无法互动。

「设置 → AI 服务」为当前登录账号保存一个 DeepSeek Key，分别控制文案生成（直播及视频发布）与观众互动是否允许使用。本场开关不改变账号用途开关。账号 Key 加密保存在 Cloud，仅由所属设备的有效会话读取，浏览器不回显。设备通常一分钟内同步；保存成功不代表服务额度或设备已验证。

准备阶段不显示运行记录；开播或启动过程中显示互动状态、开关、活动记录和恢复操作。运行中切换开关同步本场完整配置，控制操作期间拒绝竞争修改。设备离线显示状态未知，必要错误和恢复入口保留。

## 配额与成本

聊天会调用 DeepSeek 付费 API。YouTube 当前每条 `liveChatMessages.insert` 消耗 50 单位，同一 Google 项目的频道共享配额；默认普通接口桶为每日 10,000 单位。没有应用层每日上限并不代表无限配额，聊天耗尽额度也可能影响同项目其他 YouTube 操作。

每日配额耗尽后暂停互动，按 `America/Los_Angeles` 的午夜恢复；发送限流和临时网络故障使用退避重试。面板提供错误原因与处理入口，不显示上游原始请求或错误正文。

来源：[YouTube 配额](https://developers.google.com/youtube/v3/determine_quota_cost)、[聊天发送](https://developers.google.com/youtube/v3/live/docs/liveChatMessages/insert)、[长连接接收](https://developers.google.com/youtube/v3/live/streaming-live-chat)。官方配额表未单独列出 `streamList` 成本，本功能不承诺它免费。

## 运行与恢复

每个实例拥有独立运行器、设置、队列和加密检查点。独立 Agent、桌面内嵌 Agent 与单机 local 服务均由进程启动聊天，关闭网页不会停止互动；Cloud 管理身份、配置投递与状态，不持有 YouTube 令牌，也不调用聊天 AI。

首次启用只处理启用之后的新留言。同场断线使用持久化游标恢复；消息 ID 去重，本频道消息和重复刷屏被过滤。模型获得有限的本场个人与公共对话，观众文本不能覆盖系统规则，模型没有 OBS、开停播或其他控制工具。

发送前重新确认设置与场次，并先保存发送中记录。发送成功保存 YouTube 返回的消息 ID；超时、断线或进程崩溃造成结果不确定时，不自动重发该条消息。应用不会声称 YouTube 支持 exactly-once 发送。关闭开关、停播、换场次或退出进程会取消生成并清空待发送内容；已提交给 YouTube 的消息无法通过关闭开关撤回。

Key 无效、余额不足或授权失效时暂停并等待处理，避免持续付费重试。用户修正账号 AI 设置并等待设备同步后重新检查条件；重新授权原频道也会解除授权暂停。聊天关闭时等待可用的新场次。客户只操作自己的设备，管理员通过相同目标入口协助；设置操作记录操作者、实例及结果，审计不记录消息或密钥内容。

## 接口、升级与验收

`POST /api/live-chat` 接受 `read`、`configure`，显式指定实例，Cloud 模式还须指定设备。配置包含 `enabled`、`preset`、`customPrompt` 和 `intervalSeconds`。读取与保存配置返回受限聊天状态，浏览器提交 Key 被拒绝。

Cloud 声明 `account-ai-v1`，Agent 通过 `POST /api/agent/account-ai-environment` 读取自己的设备所有者配置。路由拒绝浏览器 Origin、错误 Host、未配对、失效会话和撤销设备，不接受客户端指定账号。公开设置接口 `GET/POST /api/account-ai` 以当前会话隔离账号，严格 schema、修订号和文件事务防止越权与并发覆盖。

新版 Agent 声明 `configuration.accountAi` 和 `liveChatSelection`。账号设置保存后，文案与互动都使用账号 Key；被禁用的用途或缺失 Key 不回退旧 Key。首次同步失败时禁用 AI 并自动重试，后续同步失败保留最后确认的策略。未创建账号设置时保留旧实例文案 Key / 管理员互动 Key 的兼容行为，原文件和 YouTube 授权不删除。旧客户端使用新本场参数前会被要求升级。

运行依赖 `@grpc/grpc-js` 和 `@grpc/proto-loader` 纳入生产依赖，桌面 Agent 将其打入内嵌 Node bundle。官方 `streamList` 的必要 protobuf 字段描述内嵌于代码，部署不依赖外置 `.proto` 文件或运行时下载协议资源。

新 Agent 在心跳的 `configuration.liveChat` 中声明能力，并提供可选 `liveChat` 状态。旧 Agent 心跳继续兼容；网页提前显示升级提示，不向旧版本投递未知任务。升级顺序为 **Cloud → Agent / 桌面安装器**，保留原数据目录、实例 ID、OBS 设置、加密密钥和频道授权。回退保留新增聊天检查点，旧版本不会执行聊天。

自动验证使用合成频道、消息、授权与模拟 gRPC/HTTP。测试通过、构建成功和界面截图都不能证明真实观众收到回复。真实验收须由用户完成或授权实际直播与聊天发送，再检查观众端显示、不同语言、关闭网页后的持续运行、关闭开关及断线恢复。

## 回复生成与发送格式

生成器输出 `@观众称呼 回复内容`，发送运行器验证非空与 200 个 UTF-16 单元长度上限，不要求 `[AI]` 前缀。旧版发送器曾残留强制前缀检查，导致合法生成结果被跳过；串联回归使用真实生成器和运行器、模拟模型与发送端口验证「你好／好好听呀／不错」均可发送。此修复需要更新实际执行互动的 Agent／桌面程序，网页刷新不能替换已安装二进制；本地测试不代表真实 YouTube 已验收。

## 2026-10-18 聊天整改（当前分支，未发布）

新增八个人设与自定义、responsive / natural / addressed 三种接话模式，频道背景、昵称及长短/幽默/表情/主动提问偏好。旧 friendly / playful / gentle 标识保留。扩展字段可缺省，旧配置与加密检查点不做批量重写。编辑后显式保存 responsive；相邻两秒内同人留言最多合并四条、1000 字符，生成开始后新到的消息不会被吞掉。

模型可返回 reply / clarify / skip；正常 skip 不发送且不会作为错误重试。明显英文/拉丁字母留言被回成纯中文时最多纠正一次，仍不合适则跳过；这只是语言保护，不能代替全面多语言质量评估。昵称前缀归一化，并去掉模型自己加的前缀；同观众完全重复回复跳过。人设不冒充真实主播，不猜测未提供的声音或画面。

公共背景最多十二条，同一观众已回复上下文最多五轮；均来自本场有界记录，以作者 ID 标记，未确认发送不会冒充已发送历史。频道背景是操作者明确填写的事实，默认未知；提供「AI 音乐，未命名」便捷填入，不自动套用到所有频道。

POST /api/live-chat 新增 preview，input 包含 config、text 与最多八轮手动 history。Cloud 通过原有鉴权、设备归属和加密任务投递；Agent 声明 configuration.chatConversation，执行真实生成器，不持有 YouTube 发送端口，不改变启停、游标或直播历史。每实例单次在途、五秒冷却。预览无须开播，但需要在线 Agent 和可用模型额度；关闭网页取消等待，已交付 Agent 的模型调用可能继续完成，但不会发送聊天。试聊输入与结果按既有加密任务记录保存，审计仅记动作和目标，不记录正文。

新扩展和 preview 在旧 Agent 前被拒绝并提示升级；旧四字段启停/保存协议继续可用。升级顺序 Cloud → Agent；仅刷新网页不会替换设备上的生成器。真实直播发送、安装包和部署仍待验收。详细质量证据见 [直播聊天整改](直播聊天整改.md)。
