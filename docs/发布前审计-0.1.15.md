# 0.1.15 发布前审计

审计范围是 PR #39 相对最新 main 的完整变更，并合入单独的 OBS 启动反馈 PR #38。覆盖浏览器、Cloud、Agent、桌面和安装/发布路径，不以最后一笔提交代替整个分支。

## 逻辑与数据

- 配置包与本场数据分离：账号通用规则、目标资源在使用时选择、文案在实际流程生成；既存任务不被模板修改。
- 草稿与异步：切换路由/步骤保留输入和上传；配置类型各自保留编辑状态；AI 条件改变使旧排期不可确认。
- 新 API 使用鉴权账号派生目录，同源/长度/结构校验、修订冲突、原子保存；浏览器只获公开 AI 状态，不回显密钥。
- 迁入标记与配置原子保存，旧文件保留，删除后的直播包不从旧目录复活；频道清理前先保留通用视频规则。
- 开播操作仍由 Agent 执行，完整配置进入不可变任务快照；云端不执行 FFmpeg、不接管 OBS 或 YouTube token。

## 依赖边界

生产依赖审计为 0 项告警。开发工具链仍有 `braces`（深层 glob 导致栈耗尽）和 `sprintf-js`（无界精度造成资源耗尽）两项根因及其传递依赖告警；查询时最新版本分别为 3.0.3、1.1.3，尚无修复版。它们只处理仓库扫描模式及构建日志，客户输入不进入这些路径；不通过强制降级 Next ESLint 或安装器来掩盖告警。已有补丁的构建缓存依赖另行升级。CI 只运行可信仓库构建，仍需跟踪上游修复，不能宣称全依赖零告警。
