# 客户权限、OBS 接入与数据位置

## 使用流程

- Do / Liang：客户网页与 App 登录。ULiang / UDo：明确授予权限的管理员，使用管理员网页。管理员可创建客户及重置客户密码；大写 U 前缀不能单独授予权限。
- 旧设备默认没有客户归属，仅管理员可见。在线、空闲后在“设备归属”选择客户并分配。新邀请属于生成它的客户；管理员代生成时须选择客户。App 登录客户必须与邀请和恢复的原设备一致。
- 管理员的协助操作仍记录真实操作人；任务保存执行时的客户归属。设备归属在任务入队锁内再次校验。
- App 仅主进程保管 12 小时云端会话令牌，密码不落盘。网页 Cookie 与桌面 Bearer 会话互不通用；角色或账号版本变化会使会话失效。退出不会停止已有 OBS/Agent。
- 默认新增从安装包干净 OBS ZIP 创建，生成标准场景、随机连接密码和独立空闲端口。复制已有程序、扫描和手动接入保留在折叠高级选项，不复制旧配置、场景、推流密钥或 OAuth。
- 扫描先检查进程、安装记录、所有固定盘常见目录；完整扫描遍历固定盘，支持取消。系统目录、目录链接和不可读位置列入跳过列表，不能宣称发现所有未访问位置。
- 连接诊断展示实例、原因及定向操作。未启动不阻挡前面的电脑准备步骤；准备状态按每个 OBS 单独判断，非阻塞技术检查不参与完成判定。托管 OBS 可经系统授权自动限制控制端口，不开放公网端口。
- 第二路空闲时新增，电脑无需再次配对；仅新实例需要频道和素材，第一路配置保留。每个实例必须独立绑定频道。

## 安装和数据位置

NSIS 安装向导分别选择程序安装位置和 LiveNest 数据父目录；D 盘只是建议，不再静默创建默认数据位置。已有安装沿用原位置，安装资源与数据目录不能相同或相互包含。未知非空目录和目录链接拒绝接管。

加密桌面配置随 OBS、素材和状态统一存入数据根目录；AppData 保留非敏感定位记录和旧密文备份。设置中的迁移需关闭所有相关 OBS，经过维护确认、Agent 停止、完整复制与摘要校验、托管路径修正，才切换位置并恢复连接。失败副本与原目录均保留。当前实现与验证见[本地数据与独立 OBS](desktop/本地数据与独立OBS.md)，下方版本验收为历史记录。

## 数据和接口

- Account 使用 admin/customer 角色；只有显式 admin 且大写 U 开头才是管理员。升级先备份，再运行 scripts/migrate-account-roles.mjs，保留密码，撤销降权账号旧会话。登录不再自动添加内置账号。
- Agent 增加可空 owner；空值表示待管理员分配。
- `/api/desktop/session` 为客户专用 Bearer 会话，不能使用浏览器 Cookie；`/api/admin/overview` 和 `/api/admin/assign` 要求管理员。
- 浏览器设备、状态、控制、上传全链路、OAuth 开始及回调、移除与恢复配对检查客户归属；本地旧控制服务仅管理员可用。
- 已有 Agent 的心跳、轮询和设备凭据保持兼容。旧 App 的匿名配对入口关闭，用户需更新后以客户账号配对。
- 全局面板每 5 秒刷新，沿用 20 秒新鲜度；离线、过期或无法确定的 OBS 状态为未知。OBS 是否推流与 YouTube lifecycle 分列。

## 部署

1. 保留 `/etc/livepilot/cloud.env`，备份持久化 access/设备状态，先部署兼容旧 Agent 心跳的云端。
2. 在云端正确配置环境执行 `node scripts/provision-accounts.mjs`，通过标准输入提供 Liang/ULiang/UDo 的指定密码 JSON。仅创建缺失账号并更新指定角色；重复执行不改已有密码和禁用状态。密码不得进入源码、命令行参数或发布日志。
3. 验证管理员和客户登录、设备过滤、拒绝管理员 App 登录，再发布 0.1.2 NSIS 安装包。旧设备由管理员分配，不自动猜测客户归属。
4. 回退不得恢复旧的共享权限版本对外服务，也不得用旧备份覆盖更新后的运行状态；保留安全版本并向前修复。
