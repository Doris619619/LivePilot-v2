# 客户报错与恢复操作改造验收

日期：2026-09-23。基线：远程 main `d39b30d22a003b3ab0a0669731607d5152191d21`。在本地主目录修复分支开发，无新工作树；原分支与审计工作树保留。

## 错误契约和兼容

`src/shared/problems.ts` 定义 `Problem.version = 1`、原因码、来源、领域、原目标、严重程度、阶段、结果确定程度、发生时间、可选尝试身份、安全上下文及白名单动作。`core/errors` 只信任已登记的应用说明与 errno 白名单，未知异常不透传。复制摘要排除自由文本、上下文与原始输入。

HTTP 保留 `{ error }`，可增加 `problem`。业务频道／设备凭据失败不注销客户；明确客户会话 401 才触发登录。桌面 IPC 返回成功、失败或取消；失败保留输入。动作执行前仍由宿主、服务端核验身份与条件。

Agent 在原 session 响应读取 `capabilities: ["problem-v1"]`；仅在云端声明支持后汇报新字段。无能力声明时剥离 problem、problems、authorization、query、processKnown、verification。新云端 schema 接受缺少新字段的旧快照、报告及上传记录。既有任务 ID、去重、租约和设备身份规则保持不变。

浏览器等待上限：普通读取 15 秒、提交 30 秒、状态及 Agent RPC 60 秒、上传分片 120 秒。超时只是停止等待；控制写请求不自动重发。网页与桌面均独立更新读取时钟，超过 20 秒的旧值不能支撑“新鲜状态”。

OAuth 结果保存 10 分钟的随机引用，只允许原用户、仍有原设备权限的用户读取；引用不含 code/state/token。回跳保留原实例。过期结果要求重新查询实际频道，不重放授权。
