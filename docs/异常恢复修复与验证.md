# 异常恢复修复与验证

审计基准为 `f713e6b`。本次修复只覆盖非配额项，F06 及其请求节拍、缓存和额度策略留给独立工作处理。原工作目录中的直播质量诊断改动不属于本分支。此文记录源码行为，不代表已经部署或完成真实直播验收。

## 1. 直播与素材

| 问题 | 修复后的恢复规则 | 回归入口 |
| --- | --- | --- |
| F03 已删除的推流对象反复复用 | 查询权威确认不存在、OBS 已停止且原广播未开播时，只替换该推流对象并重绑原场次；未知查询结果不替换 | `tests/control.test.ts` |
| F04 原场次只能检查，无法继续 | 已保存身份/意图、状态新鲜且可准备时，明确点击「继续本场开播」沿原意图推进；中断的 OBS 启动可显式确认，不自动开播 | `tests/broadcast-recovery.test.ts` |
| F07 创建前失败后素材回滚 | 只有已产生场次身份或创建意图才固定执行快照；尚未创建场次的失败不覆盖草稿，刷新和重新打开都保留选择 | `tests/broadcast-recovery-ui.smoke.mjs` |
| F08 下一场前置失败复活旧场次 | 新开播产生副作用前的频道/素材检查失败保留上一场终态，不读取旧广播作为下一场前提 | `tests/control.test.ts` |

素材锁定提示提供当前场次的处理入口。已确认 YouTube complete 且 OBS 未推流时，点击「解锁素材」仍由 Agent 重新核对并完成旧场次，不直接删浏览器状态。正在直播、未知结果、正在处理和过期快照继续受保护。

## 2. 上传、绑定、发布与桌面

以下模块由同一分支的对应恢复实现与定向回归覆盖，具体契约见 [频道与上传恢复验证](频道与上传恢复验证.md)、[视频发布异常恢复](视频发布异常恢复.md)、[桌面异常恢复与实例生命周期](桌面异常恢复与实例生命周期.md)。统一原则为：保留原工作、明确可执行下一步、成功反馈对应实际确认层级。

| 审计项 | 恢复边界 |
| --- | --- |
| F01 | 授权需恢复与主动删除分离；保留工作和视频关联，同频道明确重新授权后恢复；写请求不盲目重放 |
| F05、F15 | 成功换绑才释放旧频道，迟到确认不得抢回；明确取消只释放自己的授权活动 |
| F09、F10 | 已完成上传可离线退出进入下一份；服务器找回记录同步原类型和目标，未完成取消仍核对服务端 |
| F11、F12 | 归档不永久封禁文件夹名，旧草稿保持版本保护；活动任务的重要修订不受首次预上传窗口延迟 |
| F13、F18 | 已上传视频在原 videoId 上修复受限元数据；恢复自动排期保留当前编辑文案 |
| F02、F14、F16、F17 | OBS 修复使用局部配置，正式手动连接可安全修正，重连重新读取代理，首次配置失败可重新选择或恢复编辑 |
| G01、G02、G03 | 名称作为元数据更新；原数据位置故障有只读恢复；正式实例可安全退休或恢复缺失程序，保留文件与历史 |

G03 的退役只对满足空闲检查、没有关联独立发布账号的非 main 实例开放。main 与仍关联账号的实例保留身份，通过「恢复缺失程序」继续使用；不会以删除授权作为恢复前提。

与配额保护实现组合时，已发起停止或平台待收尾的场次不能显示「继续本场开播」。新鲜查询确认平台结束后显示确认解锁；两端收尾完成后，保留的停止审计标记不阻止下一场开播。协议兼容保留恢复与配额两组能力，400 才逐级降级，认证、权限及暂时故障不降级。

组合回归使用真实 Cloud、RPC、Executor 与 Runner，Google 返回合成响应：同频道重新授权保留原 videoId，迟到授权不能越过新的失效代际；GET 的第二次读取单独准入，POST／PUT 在 401 刷新后不自动重放。恢复测试显式建立合成配额基线，不依赖未知历史默认放行。
