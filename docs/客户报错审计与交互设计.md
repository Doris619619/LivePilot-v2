- 方法：静态追踪“产生错误 → 保存/传递 → 状态转换 → 展示 → 恢复操作”。阅读现有测试用于判断覆盖范围；本轮未执行测试、构建、浏览器模拟、真实 OBS 操作、OAuth 或直播。

结论：当前代码仍存在报错含义混淆、原因丢失、错误不在操作现场、恢复动作不匹配的问题。本次归纳为 **26 项需要处理的缺陷或交互缺口**，详见第 3 节。不是每一项都表示业务动作会失败；有的影响客户判断，有的会直接把客户带到错误的操作上。

“所有”在这里指上述客户报错链路的系统性扫描，不表示已证明不存在任何潜在缺陷。未对真实安装版、外部服务故障和实际视觉效果作已验证承诺。

用户最初举出的旧提示，在本基准中已部分修复：`electron/obs-network.ts:41–53` 已区分未启动、端口占用、未监听、认证失败、超时和防火墙隔离未确认，并返回操作类型；正常与待操作说明也已不统一用红字。后续应保留这些改进，将同一判断贯彻到网页及 Agent，而不是再维护两套不同的含义。

## 2. 客户最终应看到什么

每一条需要处理的问题，在发生位置展示以下信息：

1. **对象与事实**：哪台电脑、哪个 OBS、哪个上传；已经确认发生了什么。
2. **影响与确定程度**：只是控制连接失败，还是直播失败；是否仍可能推流；动作是否被拒绝、已受理、部分完成或结果待核对。
3. **具体操作**：一至三步客户能执行的操作，明确在哪台电脑、哪个页面执行。
4. **就地按钮**：一个主要动作，加必要的次要动作；名称与实际动作一致。

示例一，已确认 OBS 运行但控制端口没有服务：

> **直播电脑 A · OBS 1：控制连接尚未建立**
>
> OBS 已运行，但保存的控制端口 4455 未检测到服务。当前无法读取或控制它，不能据此判断是否正在直播。
>
> 在电脑 A 的 OBS 1 中打开“工具 → WebSocket 服务器设置”，启用服务器和身份验证，并核对端口。
>
> **[查看 OBS 1 的设置步骤] [重新检查 OBS 1]**

此时防火墙一项显示“尚未检查”，不显示“防火墙故障”。托管实例可另外提供“修复连接”，但须先说明结束该实例直播/录制及关闭窗口的条件，点击后再次由宿主验证。诊断失败不能直接结束直播。

示例二，读取 YouTube 状态超时但原授权仍在：

> **OBS 1：暂时无法查询 YouTube**
>
> 原频道授权记录仍在，本次查询没有得到响应。当前 YouTube 直播状态未知。
>
> 在电脑 A 检查访问 Google/YouTube 的网络；网页能打开不代表电脑 A 能访问 YouTube。
>
> **[重新查询] [查看该电脑的网络检查步骤]**

示例三，操作结果未确认：

> **OBS 2：开播结果待核对**
>
> 请求已发出，但尚未收到完成结果。OBS 或 YouTube 可能已开始处理。
>
> 先刷新本次操作和推流状态；持续无法确认时，到电脑 A 的 OBS 2 与对应 YouTube Studio 场次核对。
>
> **[查询本次操作] [查看核对步骤]**

不在这种状态下提供会新建场次的通用“再试一次”。

## 3. 问题清单与逐项方案

优先级：P1 表示容易导致误操作、错误恢复或失去关键状态；P2 表示明显妨碍定位和完成操作。本节结论来自代码分支和数据流，不是线上故障发生频率统计。

### E01 · P1 · OBS 已运行但不可控制，被显示成“未启动”，主卡片还可能“就绪”

- **证据**：`src/app/instance-console.tsx:71–97,148–149,207–212`；`src/shared/readiness.ts:4–14`；`src/core/obs/runtime.ts:18–29`。
- **触发与现状**：进程存在但密码错误、端口未就绪或控制请求失败，返回 `running=true, ready=false`。网页只看 `ready`，统一显示“未启动”并给“启动 OBS”；开播阻塞计算未检查 OBS 故障，其他条件满足时主标题可显示“就绪”。具体原因默认折叠。
- **设计**：分开“程序未启动”“程序已运行、控制未连接”“无法确认程序状态”“控制已连接”。主卡片必须露出真实阻塞原因和对应动作。未运行且支持自动启动时可显示“开播时将启动 OBS”，不必机械禁止自动启动；认证、冲突、未知状态不应显示“就绪”。
- **验收**：未运行、未监听、认证失败、端口冲突、进程查询失败分别显示不同状态；卡片收起也能看到问题和主操作。

### E02 · P2 · 诊断末端又合并了不同原因，桌面与网页原因不一致

- **证据**：`electron/obs-network.ts:40–53`；`src/core/obs/process.ts:43–61`；`src/core/obs/runtime.ts:24`。
- **触发与现状**：进程检查已经抛出“程序不存在”“配置无效”等可信错误，网络诊断最外层 `catch` 全部改成“Windows 查询超时或权限不足”；运行核心又把未监听和端口归属错误合并。程序文件检查与网络检查可对同一问题给出两种解释。
- **设计**：保留已识别的原因码；只有确实无法归类时显示“暂时无法确认”，不列举未获得证据的原因作为结论。进程、控制连接、防火墙各自有检查结果与前置条件，前置失败时后续标为“未执行”。共用判断，避免桌面和 Agent 分叉。
- **验收**：文件缺失不能变成查询权限问题；未监听不能变成端口冲突；防火墙不能在控制检查未通过时被标成已检查。

### E03 · P1 · 任意 OBS 请求失败都建议“结束直播恢复”

- **证据**：`src/core/obs/controller.ts:41–54`；调用方包括 `electron/obs-network.ts:45` 和 `src/core/obs/runtime.ts:25–27`。
- **触发与现状**：只读 `GetVersion`、场景查询和实际推流写操作共享同一句 `OBS_REQUEST`，包含内部请求名及“可通过结束直播恢复”。尚未开播或只读查询失败也会获得这条建议。
- **设计**：由动作类别决定影响与恢复：只读失败→重新读取/检查控制连接；设置请求未确认→核对实际设置；开停播请求未确认→查询本次结果。可白名单映射 OBS 状态码，但不透传原始请求、响应或密码。停止直播只在具体业务恢复条件成立时提供。
- **验收**：所有只读请求失败均不得默认建议停播；写请求超时不得断言没有生效。

### E04 · P1 · YouTube 网络、配额、服务故障被归为授权异常

- **证据**：`src/core/service.ts:54–72`；`src/core/youtube/auth.ts:14–24`；`src/core/youtube/api.ts:8–16,29–44`；`src/app/instance-console.tsx:152–153`；`desktop/app/page.tsx:78`。
- **触发与现状**：任一频道/场次/推流状态查询异常都将 `connected` 改为 false。网页显示“授权异常”，桌面显示“尚未授权”；Google token 接口任何非成功状态都被归为授权失效/OAuth 配置不匹配。
- **设计**：分别保存授权记录、授权有效性、远端查询状态。只有明确的授权失效要求重新授权；429/配额耗尽提示等待并由管理员处理；5xx/网络超时提供重新查询；应用配置错误指向管理员。原有频道名保留并标明查询时间。
- **验收**：Google 5xx、429、网络中断、明确无效授权、客户端配置错误分别有正确责任人和动作；普通查询故障不诱导反复授权。

### E05 · P1 · 桌面会话检查遇到服务器故障也清空登录态

- **证据**：`electron/auth.ts:24–29`；`electron/main.ts:57,59`；`desktop/app/login.tsx:15`。
- **触发与现状**：会话验证返回 500、503 等非成功状态时，客户端调用 `clear()` 并提示“登录已失效”。403 的设备归属原因也可能在随后登录轮询中被覆盖成统一过期提示。
- **设计**：登录失效、设备无权限、服务暂不可用分别处理。服务暂不可用时保留本机会话记录，暂停需实时授权的操作并给“重新验证”，绝不通过保留会话绕过服务端权限校验。权限错误显示“联系管理员分配这台电脑”，不让客户不断输密码。
- **验收**：401/403/429/500/503/网络中断逐项验证；原 Agent 与直播不因界面会话验证失败而被停止。

### E06 · P2 · 配对丢弃服务端具体原因，错误指向“更新网页”

- **证据**：`electron/pairing.ts:17–23`；`src/cloud/agents.ts:33–80`；`src/app/api/agent/[...path]/route.ts` 的配对认证入口。
- **触发与现状**：403 客户归属不符、409 等拒绝与服务异常统一变为“请确认网页已更新”；401 同时包含客户登录、邀请码、本机旧身份多种问题，却统一要求重新生成配对码。
- **设计**：云端给稳定且不泄露其他客户身份的原因码；桌面显示对应的“重新登录”“重新生成配对码”“在原 Windows 账户恢复”“联系管理员分配”“稍后重试”。响应丢失继续复用原配对身份，不重新建电脑。协议缺字段仅称“服务响应不兼容/未确认”，有版本证据才要求升级。
- **验收**：错客户、过期码、已用码、旧身份不符、未授权客户会话、服务异常和响应丢失不会互相冒充。

### E07 · P1 · Agent 通信抹掉根因，上游 401 还能被网页当成客户登录失效

- **证据**：`src/agent/transport.ts:21–29`；`src/agent/desktop-worker.ts:18–20`；`src/agent/executor.ts:52–53`；`src/agent/worker.ts:41`；`src/cloud/tasks.ts:123–133`；`src/cloud/relay.ts`；`src/app/api/uploads/[id]/route.ts:22–28`；`src/server/http.ts:15`；`src/app/client-request.ts:10`。
- **触发与现状**：除维护开始的一类 409 外，Agent 丢弃云端错误体。设备会话冲突、频道占用、Google bootstrap 缺配置等只剩 `CLOUD_REQUEST`。一个在途上传分片下载若收到 Agent 401，其状态可经 Worker→RPC→上传接口传到网页；网页对任何业务 401 都触发客户登录失效事件。
- **设计**：保留安全原因码、来源和作用域；HTTP 401 在浏览器边界专用于浏览器会话认证失败。Agent/YouTube 认证故障作为业务问题返回，指向对应设备或频道。跨进程传递结构化结果，不将 `Error` 的类身份或消息文本当协议。
- **验收**：客户会话仍有效时，上游凭据失效不能退出工作台；频道被占用要明确解释并给安全协助入口；云端 Google 缺配置要指向管理员。

### E08 · P2 · 一端暴露原始系统异常，另一端只剩万能“检查配置网络”

- **证据**：`electron/manager.ts:41,139`；`src/core/errors.ts:13–14`；`src/core/storage.ts:27–43`；`src/core/ownership.ts:12`；`src/server/http.ts:15`。
- **触发与现状**：桌面 `Manager.error` 对普通 Error 直接取 message，文件复制/写入等异常可能是英文系统文本及路径；核心端未登记错误统一丢成通用提示。`claimHost` 将打开锁文件的所有失败都说成配置已被进程占用，包含权限和磁盘错误。
- **设计**：在文件、进程、网络边界按白名单识别原因，区分权限、空间不足、文件缺失、竞争及未知错误。面向客户显示目标电脑和操作步骤，技术细节单独收起；未知错误保留阶段与支持编号，不猜网络原因、不承诺零副作用。不要为了清晰而开放原始异常透传。
- **验收**：EACCES、ENOSPC、ENOENT、锁竞争分别有不同指引；浏览器和诊断复制件不包含凭据、完整上游请求及未经允许的本机路径。

### E09 · P1 · 启动失败覆盖“使用原 Windows 账户”的关键恢复信息

- **证据**：`electron/settings.ts:15–19`；`electron/main.ts:38–49,70`；`electron/windows-credentials.ts`。
- **触发与现状**：本机配置解密失败已经有具体提示，但顶层启动异常统一变成“检查配置文件权限或重新安装”，随后退出。重新安装不能解决用户身份与加密配置不匹配。
- **设计**：启动也使用安全问题目录；已识别的解密错误保留“使用原 Windows 账户、保留原配置”。启动失败窗口提供相应的离线步骤与“复制诊断摘要”，不要求先登录主界面才能读帮助。资源损坏才给安装修复入口。
- **验收**：换 Windows 账户、配置损坏、目录不可写、程序资源缺失显示不同恢复方案；提示不会引导删除授权文件。

### E10 · P1 · 快照及结果落盘失败缺少能到达客户的原因

- **证据**：`src/agent/runner.ts:20`；`src/agent/main.ts:43`；`src/core/service.ts:48,73`；`src/agent/worker.ts:33–42`；`electron/agent-host.ts:54`；`src/server/remote.ts:25–28`。
- **触发与现状**：读取直播状态文件或命令记录失败，快照循环直接吞掉异常，只保留旧快照；最终网页只显示“状态读取已过期”。任务结果持久化失败仅写 stderr，而桌面 Agent 的 stderr 被忽略，任务可能长时间显示执行中或待核对。
- **设计**：保留最后成功快照，同时单独上报“此实例读取失败/结果保存失败”的安全问题及时间。反馈通道不依赖同一已故障的持久存储；通过 IPC/心跳内存状态尽力汇报。连接心跳与业务快照健康度分开显示。落盘失败时执行结果为待核对，不自动重放任务。
- **验收**：状态文件损坏和结果保存失败时，客户能知道应检查哪台电脑的磁盘/权限；通讯仍在线不能消除业务读取故障。

### E11 · P1 · 桌面状态读取失败后，新鲜度时钟与旧提示处理不正确

- **证据**：`desktop/app/page.tsx:27,37–50,68`；`electron/manager.ts:38`；`electron/agent-host.ts:61,66`。
- **触发与现状**：`now` 只在状态读取成功时更新；读取持续失败时，旧 `online` 和快照有效性可停在过去。成功读取也不通用清理本地读取错误，旧 `manager.message` 优先于新 Agent 信息；Agent 的心跳又会清掉共享 message，包括保存 Google 配置失败的消息。
- **设计**：独立墙钟和最近成功读取时间；超时显示“本机状态暂不可读取”，不沿用绿色在线结论。连接错误、业务错误、持久化错误各有身份和清除条件：连接恢复只消除连接问题，保存问题只有保存成功才消除。保留故障历史但不继续占用当前告警。
- **验收**：读取失败跨过 20 秒、恢复后再次失败、配置保存失败后收到心跳等序列均不发生假在线、旧错压新错或误清故障。

### E12 · P1 · 通用重试丢失失败 OBS 与原操作

- **证据**：`src/shared/desktop.ts` 的 `DesktopActivity`；`desktop/app/page.tsx:59–61`；`desktop/app/setup-feedback.tsx:8–11`；`electron/manager.ts:184–185`。
- **触发与现状**：失败活动只记录 action/step，没有目标 ID；第二个 OBS 失败后，“重新检查 OBS”调用不带 id 的 `prepare`，宿主可能选择第一个候选或第一个正式实例。重命名、修复等也被转换成准备 OBS；失败标题还隐藏了原 stage。
- **设计**：记录安全的操作身份、目标 ID、失败阶段及恢复动作，敏感输入不落盘。错误卡保留“OBS 2 · 检查控制连接失败”，按钮明确“重新检查 OBS 2”。重命名失败回到同一名称字段，手动连接失败回到同一实例表单，不能按步骤号猜动作。
- **验收**：多实例、候选与正式实例共存时，每个恢复动作只针对原对象；旧错误不能作用于后来选择的对象。

### E13 · P2 · 六步配置的完成状态与阻塞位置对不上

- **证据**：`desktop/app/page.tsx:46–56,75–80`；`electron/manager.ts:137`；`electron/diagnostics.ts:21–27`。

## 4. 统一状态和提示规则

### 4.1 将五种事实分开

| 维度 | 建议状态 | 不能推导的结论 |
| --- | --- | --- |
| 客户账号 | 未登录、已登录、待验证、权限不足、已失效 | 账号在线不代表设备在线 |
| 设备通信 | 未配对、连接中、在线、重连中、凭据失效、会话冲突、未知 | Agent 心跳正常不代表 OBS 可控 |
| OBS | 程序未运行、运行状态未知、运行但控制未连、控制已连接 | 控制未连不代表无声音/未推流 |
| 频道 | 未授权、原授权存在且查询正常、授权失效、查询受阻、状态未知 | API 配额/网络错误不代表需要授权 |
| 业务操作 | 未发出、明确拒绝、已受理、处理中、完成、部分完成、结果待核对 | HTTP 202/超时不等于最终成功/失败 |

维护阻塞、素材读取健康、防火墙检查作为各自问题，不塞进“网络错误”一栏。OBS 是否自动启动由原控制流程决定；“就绪”仅在所展示的就绪条件真实满足时出现。

### 4.2 严重程度与布局

- 普通信息：尚未准备、用户取消、主动暂停、正在自动重连；用文字状态，不默认红色。
- 待处理：明确配置缺失、权限需要客户操作、连接失败阻塞当前操作；就地醒目的问题卡。
- 需核对：外部状态或操作结果未知；明确“可能仍在推流”，提供核对入口。
- 紧急影响：有证据的直播异常或数据保存失败；首屏/实例摘要持续显示，必要时使用主动告警。正常后台轮询不反复播报。
- 一处问题只有一张主卡；顶部汇总只列“2 项待处理”和定位入口，不把同一句重复刷满多个位置。
- 全局条只用于账号、整个服务或整个设备层故障；实例、文件、字段的问题放在各自附近。收起后保留摘要及主操作，技术详情可折叠，客户操作步骤不可全藏进技术详情。
- 提示同时使用文字和语义标记，不只靠颜色；新增错误使用合适的 `role=alert`，处理中用 `role=status`。轮询不抢焦点，提交失败定位到出错字段，窄屏不隐藏操作。

设计依据为本次已阅读的 apple-design 技能所附 Feedback / Writing / Accessibility 原则：反馈靠近对象、说明不可执行原因、错误提供具体纠正步骤、重要状态不只靠颜色。此次未进行像素、对比度或读屏实测，以上是待实现的验收要求。

### 4.3 错误生命周期

问题身份由“作用域 + 目标 + 原因 + 操作尝试”组成，不能共用一个 message 槽。每条有首次发生时间、最后确认时间、当前/已解决状态。读取失败不能覆盖业务执行结果；新的轮询只结算它实际证明恢复的问题。

客户关闭的是提示展开状态，不是业务故障。仍阻塞操作的问题在对象摘要中保留；已解决问题退出当前列表，可留在短期诊断历史。未知外部状态不会因客户点击“关闭提示”而变成成功。

## 5. 错误契约及恢复动作设计

### 5.1 需要保留的信息

这是一份拟议契约，不是已添加的代码。复用当前 `AppError` 安全边界，分离内部异常与可公开的 `Problem`：

| 字段 | 用途与限制 |
| --- | --- |
| `version / code / domain` | 稳定版本、细分原因、发生于账号/设备/OBS/频道/素材/更新等域；不能继续用一个 BUSY 表示所有原因 |
| `scope / target` | 设备、实例、上传、操作 ID；客户端通过其已授权数据得到显示名，服务端逐次校验权限 |
| `severity / certainty` | 严重程度；已确认事实或尚未确认，不能把推测升级成事实 |
| `stage / outcome` | 失败阶段及未发出/拒绝/受理/完成/部分完成/待核对；由操作边界记录，不能从 HTTP 状态猜全部结果 |
| `observedAt / attemptId / requestId` | 决定是否过期、是否属于同次尝试、何时可以清除旧提示 |
| `safeContext` | 白名单数据：必要的名称引用、端口、缺少的源名、剩余空间/限额、等待期限；浏览器不带绝对路径或秘密 |
| `actions / helpTopic / supportRef` | 白名单动作描述、主题和诊断引用；不是任意命令或任意 URL |
| `message` | 安全文字兼容旧版本；完整中文标题/影响/步骤优先由统一目录按场景生成 |

内部保留可分类的系统原因和上游状态，但它们不直接序列化到客户端。只白名单取上游 reason/code，不保存原始请求体、响应体、token、密码、推流密钥、OAuth code、配对码或代理凭据。

诊断摘要至少包含当前版本、发生时间、对象、阶段、公开错误码、操作结果和最近状态时间。桌面文件路径仅在用户查看本机详情时按需显示；复制给管理员的默认摘要脱敏。支持编号用于关联本机/服务端安全事件，不承诺已建立外部客服系统。

### 5.2 可实现的动作类型

| 动作 | 具体含义 | 必须保证 |
| --- | --- | --- |
| 重新读取/诊断 | 重读原目标的状态，或重新执行只读诊断 | 原 agentId/instanceId 不变；不启动、停播、改配置 |
| 启动指定 OBS | 仅当确认未运行时启动对应程序并检查 | 仍用真实路径身份及端口归属验证；明确不会开播 |
| 修复托管连接 | 打开修复条件说明，用户显式执行后走已有维护逻辑 | 确认目标已停止；不杀占用端口的其他程序；手动实例不自动修复 |
| 打开具体设置/帮助 | 对应字段、帮助主题或受限 Windows 设置入口 | 使用固定白名单；无法直达 OBS 内部设置时诚实显示操作步骤，不假装已打开 |
| 前往网页目标 | 打开已授权电脑/OBS/上传的位置 | 不丢目标；不把所有故障送回网页首页 |
| 重新授权原频道 | 仅明确授权失效时发起 | 有未结束场次时遵守原频道约束；不会自动切换频道 |
| 查询/继续上传 | 查询原 uploadId，核对偏移及文件身份后继续 | 保留原目标和幂等标识；取消仅清临时上传 |
| 查询控制结果 | 查询同次命令及外部实际状态 | 不自动发一个新开播任务 |
| 联系管理员/复制摘要 | 提供具体需管理员处理的事项及脱敏诊断 | 不泄露其他客户信息；没有配置联系方式时不生成虚假客服入口 |

远程网页不能直接打开另一台电脑的系统设置或 OBS 窗口。此类主动作应写“在电脑 A 处理”，展开具体步骤，辅以“处理后重新检查”。桌面端才提供本机系统入口；新增远程能力不属于本设计的必要条件。

### 5.3 兼容现有云端和旧客户端

不能只改 UI 或往响应里加 code 就认为完成。需要贯穿 `AppError → Service/Commands → TaskReport/快照 → Cloud → HTTP/IPC → UI`，同时保留旧 `error/message` 文本供降级。

- 新云端先接受并校验可选问题字段，继续兼容只有字符串的旧 Agent。
- `reportSchema` 当前使用 `.strict()`；直接向旧云端发送新字段会被拒绝。须协商 `problem-v1` 能力，或在明确升级协议后才发新字段。无能力时发原协议，绝不能破坏心跳/结果回报。
- `dashboardSchema / operationSchema / uploadStatusSchema` 同步扩展；否则对象字段会被剥离，问题看似上报却到不了前端。
- IPC 返回显式结果对象，或采用统一的结构化异常封装；不依赖 Electron 拼接的异常前缀，也不以 WeakSet 身份跨进程识别。
- 持久命令和旧上传记录读取向后兼容。缺新字段时显示保守“旧版未提供具体原因”及核对步骤；不根据中文字符串关键词自动执行修复。
- 网页和管理员先发布兼容展示，Agent/桌面随后发布。旧客户端不会因网页上线自动获得本机诊断能力；验收需记录云端、Agent、桌面三者版本。
- 本次未实施以上升级，也未核对现有安装包/线上服务是否已包含任何后续改动。

## 6. 各类问题的客户处理目录

此目录覆盖现有错误家族及默认兜底；文字是拟议成品行为，实施时由统一目录维护，不在每个 catch 中复制。

| 场景/现有代码家族 | 报错核心信息 | 客户就地动作与责任人 |
| --- | --- | --- |
| LOGIN / RATE | 账号密码不符；或尝试过多与可重试时间 | 原字段修正；到期再登录；不清配对 |
| AUTH / FORBIDDEN / OWNER | 会话过期、客户未获这台电脑权限分别说明 | 重新登录；或复制设备摘要联系管理员分配 |
| HOST / ORIGIN / MODE / PROTOCOL | 访问地址、请求来源或版本不兼容 | 返回正式入口；有证据才提示更新对应端；持续失败交管理员 |
| 配对码错误 / 原身份错误 | 配对码与本机身份分开 | 新码重试；或原电脑原 Windows 账户恢复；未知结果复用旧身份 |
| AGENT_AUTH / AGENT_SESSION / AGENT_BUSY | 已撤销、会话过期、同身份已有进程分别说明 | 恢复配对；重新连接；关闭经确认的旧客户端后重试 |
| AGENT_CONFIG / INSTANCE / TARGET | 原清单待同步或对象已变化 | 刷新原设备清单、在原客户端恢复；不自动新增身份 |
| CLOUD_NETWORK / CLOUD_REQUEST | 哪一端无法连接、是否自动重连 | 系统网络/代理步骤、重新连接；服务器故障联系管理员 |
| CONFIG / Google bootstrap | 本机配置缺失与云端配置缺失分开 | 本机字段定位；Google 应用配置由管理员处理 |
| OBS_PATH / 资源缺失 | 哪个实例程序不可访问；尚未确认缺失还是权限问题 | 查看对应路径检查步骤；确认资源损坏后修复安装；保留配置 |
| OBS_PROCESS / 查询超时 | 无法读取进程，不猜测“未运行” | 重查；系统权限/负载检查步骤；提供摘要 |
| OBS 未运行 | 指定程序确实没有运行 | 启动该 OBS 并检查；不表示要开始直播 |
| OBS 未监听 | 程序运行但保存的控制端口没有服务 | 对应 WebSocket 设置步骤、核对端口后重查 |
| OBS_PORT 冲突 | 指定端口有其他占用 | 托管连接修复条件；手动实例参数步骤；不结束其他进程 |
| OBS_AUTH / OBS_TIMEOUT | 密码不符与无响应分开 | 同实例连接设置/重查；不默认停播 |
| OBS_REQUEST | 读取/设置/开停播哪个阶段未确认 | 重新读取或查询操作结果，按原阶段恢复 |
| 防火墙隔离未确认 | 已发现监听范围，但尚无隔离证明 | 本机防火墙操作步骤与复查；不暗示关闭防火墙或开公网端口 |
| OBS_SCENE / OBS_AUDIO | 缺少哪个场景/源或存在全局音频 | 对应图解；说明何时需先停录制/推流；检查后再继续 |
| OBS_MEDIA / MEDIA | 文件不可读取、格式不支持、解码失败分开 | 重读目录、选原文件或更换可播放素材；指出目标电脑 |
| Google/YouTube 网络、5xx | 授权记录保留，查询/请求未确认 | 原电脑网络检查与重新查询；已发写请求先对账 |
| GOOGLE_AUTH / YOUTUBE_AUTH | 确认授权失效 | 重新授权原频道；配置不符另交管理员 |
| 配额与直播权限 reason | 等待配额、未启用直播、频道受限 | 可重试时间（仅有证据时）；对应 YouTube Studio 步骤；不反复授权 |
| CHANNEL_IN_USE / CHANNEL | 当前频道不能分配或必须用原频道 | 选择其他频道或管理员协助核对归属；不以移除整台电脑作为默认修复 |
| INGEST / BIND / RECOVER | 哪个场次、哪一步与 OBS 状态不一致 | 查看场次、刷新、恢复原场次或显式结束；不暗中另建直播 |
| UNCERTAIN / AGENT_TIMEOUT / interrupted | 操作可能已生效，结果未知 | 查询同次操作、现场核对；保持互斥，不自动重放 |
| STOP_YOUTUBE / OBS_STOP / OBS_OFFLINE | YouTube 与 OBS 哪一步已完成/未确认 | 对应场次/OBS 的手动步骤，再查询/重试结束 |
| OBS_BUSY / OBS_FOREIGN | 存在不属于当前操作的推流 | 去对应 OBS/Studio 核对；不由诊断按钮停止 |
| 上传 SIZE / INPUT | 实际文件大小、允许上限或字段错误 | 选符合限制文件、字段就地改正；不只说“无效” |
| 上传 OFFSET / HASH | 偏移待同步、分片不同或完整文件损坏 | 查询原进度；选同一文件；确认损坏后取消临时上传再重传 |
| 上传 SPACE / RELAY_BUSY | 目标电脑空间、云端空间、传输槽等待分别说明 | 本机整理/管理员扩容/稍后继续；保留已确认进度 |
| 上传过期 / 不属于当前账号 | 无法继续的原因和范围 | 原账号查询；确认过期后重新上传；不暴露他人记录 |
| MAINTENANCE / BUSY | 哪个对象的哪个活动阻塞 | 原上传/频道/实例入口；期限与复查；必要时管理员核对 |
| STORAGE / HOST_BUSY | 读写失败、配置锁被占用、密钥不可解分别说明 | 本机权限/空间/原账户步骤；锁和加密问题交管理员，不删数据 |
| 更新失败 | 检查、下载、校验、安装准备分别说明 | 重新检查/下载、磁盘步骤、官方安装入口或管理员；不绕过校验 |
| 未识别异常 | 当前步骤未完成，能否确认执行结果 | 只读复查+复制摘要+对应责任人；不猜原因、不声称操作已撤销 |
