# 桌面异常恢复与实例生命周期

## 1. 连接修复

- 自有 OBS 的“修复连接”要求关闭目标 OBS。两次进程检查使用同一份不可变目标配置；其他实例的空闲检查不再改写进程级配置。
- 手动 OBS 的“保存并检查”同时支持待配置候选和正式实例。正式实例先用新端口、密码核对推流与录制状态，再进入维护；验证失败保留旧连接和身份。
- 维护仍检查其他实例、云端场次、上传、频道授权、发布任务和未知结果。桌面从真实本地检查生成最多 20 秒的 `verifiedIdle` 证明；该证明只补充目标旧 OBS 连接未知，不放宽正在推流或未结束场次。
- 旧 Cloud 不支持新恢复协议时会要求升级，不通过撤销授权或无证明重试绕过保护。

## 2. 重新连接网络

用户点击“重新连接”时，客户端先让旧 Agent 排空已接收任务，等待其退出与旧会话窗口结束，再启动新 Agent。新进程重新解析网络和代理配置；OBS 保持运行，不执行停播。排空失败时保留旧进程，不再启动第二个 Agent。

显式 `HTTPS_PROXY` / `https_proxy` 仍优先于系统代理。纯名称修改不会走上述流程。

## 3. 名称与候选

实例名称作为显示元数据独立保存，无需其他 OBS 空闲、全机维护或重启 Agent。保存失败时输入框恢复宿主已保存的名称，错误反馈保留。

已撤销候选的“恢复编辑”只恢复可编辑记录，不连接 OBS、不检查旧密码、不自动初始化。用户修改连接后再保存检查。尚未配对的首次手动候选还可明确改用内置 OBS；原外部程序、凭据记录保留为弃用候选，原文件不修改。

## 4. 原数据无法加载

普通工作窗口建立前，原生恢复对话框提供“重试原位置”“重新定位原数据”“复制诊断”和“退出”。不会因读盘失败创建空身份或静默选择其他目录。

重新定位仅接受已记录的同一 `rootId`，并用当前 Windows 账户解密原配置、核对配置原路径和宿主锁。原位置仍存在时拒绝切换到可能过期的副本。只读核验通过且用户确认后才提交位置；手动 OBS 路径、身份、密钥和授权保持原值，托管 OBS 路径在原根边界内重定位。归属、解密或定位记录无法核验时继续保留恢复窗口。

## 5. 缺失程序与安全退役

“恢复缺失程序”面向正式内置 OBS：先排空 Agent，随后要求 Windows 确认所有 `obs64` 进程均已关闭；在独立临时目录解压安装包资源，仅补齐 `bin`、`data`、`obs-plugins` 中缺失的普通文件。已有程序文件、场景、密码、素材、授权和历史不覆盖，不自动启动 OBS。无法确认进程或目录归属时拒绝复制。

安全退役仅支持非 `main` 正式实例，且不能有关联的独立发布账号或未完成工作。`main` 与仍关联发布账号的实例保留原身份，优先恢复缺失程序继续使用；不要求用户为了退役而删除授权。

退役先取得维护锁，再由云端检查已停推、场次终态、任务、上传、授权与发布状态。云端保留退役历史、释放活跃频道归属、写入不可复用 ID 墓碑；本机把实例移入退休记录，文件与授权保留。新旧 Agent 切换后才解除维护。

本机先保存退役意图。回复丢失后重复确认同一实例；应用重启且没有旧 Agent 时，先用设备身份读取不含凭据的云端真实库存。如果云端尚未提交，恢复原活跃记录供用户重新核对退役；如果已提交，采用已确认的新清单。协议、网络或清单不一致时保留意图及维护凭据，不猜测结果。
