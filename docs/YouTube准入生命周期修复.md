# YouTube 准入生命周期修复

2026-10-21 根据用户提供的审查逐项核对，基准为 PR #46 的 `560e5ec`。四项问题均得到代码、跨模块回归或该提交 CI 的支持；本文描述修复及验证，不代表生产部署或真实 YouTube 验收。项目预算、成本目录、轮询和子预算不在本轮调整范围。

## 1. 核实结果

| 问题 | 修复前的实际证据 | 预期恢复行为 |
| --- | --- | --- |
| 首次发布授权被 connected 前提挡住 | 真实 Cloud 准入、任务派发、Agent 运行时和 Executor 的 OAuth 回归在交换令牌前失败，未发送 Google 替身请求 | 未连接账号凭原有效 OAuth 完成任务交换令牌、读取频道并绑定 |

新增生命周期测试在修复前两项均失败；历史补传测试在修复前 6 项中 3 项失败，另 3 项保护性反例通过。Google 网络使用替身，Cloud 准入、账号记录、任务、设备日志与文件事务使用真实实现，没有把准入替换成全部放行。

## 2. 账号操作准入

账号归属与当前可执行操作分别核对。正常上传、元数据写入及其他发布操作仍要求原账号已连接、设备和客户归属一致，不允许回退到同实例直播凭据。

尚未连接的账号，仅在匹配的有效 OAuth 完成任务上下文内放行令牌交换与首次频道读取。核对设备、实例、账号、任务状态、期限及加密任务内容；伪造 purpose、取消或过期任务均不能代替授权事务。准入不直接把账号改为已连接。

撤销只允许对应账号当前 pending 清理请求。Executor 为清理操作携带原请求 ID；账号在清理期间仍不能重新授权、上传或改视频。待清理请求不因离线超过原提示期限而失去撤销重试能力。已删除账号不凭没有上下文的旧令牌取得额外权限；清理确认回复丢失时，沿原本机撤销检查点完成标记。

## 3. 历史事件补传

真实调用 start／finish 根据 Cloud 已持久化的 allowed 准入凭据与认证设备核对，不要求账号现在仍 connected。归属、实例、账号、方法及原调用关联上下文必须一致；迟到 finish 只补充原结果，不重复预扣、创建调用或退款。

缓存／阻断决定没有真实调用凭据，仍核对来源归属。永久无法核验、凭据已经超出保留期或时间无效的单条记录，转为脱敏缺口并逐条确认；不能冒充已验证的调用，也不能保留其他设备的账号或任务标识。相同事件与 boot／sequence 重传不重复累计。

严格 schema 仍拒绝原始 URL、Token、正文及其他额外字段。网络、磁盘、锁或损坏账本等暂时故障不发送持久确认，Agent 保留原分段后重试；缺口处理不用于吞掉基础设施错误。

Agent 在补传前再次 strict 校验磁盘中的每条记录。格式损坏的单条记录替换为新生成的安全缺口，先将安全分段落盘，再保存元数据回执；元数据失败或重启后不会漏记或重复累计，也不会上传、复制归档原始敏感字段。整个 JSON 文件、账本或磁盘不可读取时仍保留故障并重试，不猜测原内容。

Cloud 先在事件锁内检查 eventId 和 boot／sequence，再仅为新事件补写准入结果。重复标识即使携带另一条有效调用的上下文，也不能修改其结果或触发熔断。嵌套锁顺序固定为 events → budget，没有反向嵌套；预算读取后的汇总只是读事件索引。

## 4. Windows 文件互斥

同进程的同路径创建尝试先经过即时占用闸；直接控制仍立即返回 BUSY，跨进程互斥依赖文件系统的 wx 原子创建，Cloud 原有五秒短重试保持。只有 EEXIST 和同进程占用被归类为锁竞争；所有 EPERM、权限或其他未知错误原样返回，竞争者不删除已有锁。

Windows owner 在临界区完成后，持有原句柄核验 bigint 文件身份，再把自己的锁原子重命名为同目录随机 `.released` 文件，随后关闭并清理该释放名。公共锁名不进入本次删除挂起，旧 owner 的清理不会删除下一位 owner 的锁。重命名、关闭和删除的真实错误仍返回；随机释放残留表示临界区后清理未完成，公共锁崩溃残留仍需按原规则核实旧进程。

最终实现不再预先打开竞争者的锁，也不根据只读观察、PID 或短期缓存猜测 EPERM 的原因。早期删除挂起兼容层在 Windows CI 的原生正例中仍出现 EPERM，无法可靠覆盖旧版本删除窗口，因此移除这层判断，保留已实证的 owner 释放协议。混版本进程共享同一目录时，旧 owner 的删除挂起可能仍使本次操作安全失败；不承诺自动恢复，不吞权限错误。原生回归验证真实删除挂起会保留错误、不删除对方文件；原 owner 释放后，新操作可以完成。生产不调用 PowerShell，原生 helper 只用于测试。

最终代码重复 20 轮真实压力：每轮六个独立 Node、120 次临界区提交，共 120 个进程、2,400 次准确计账；互斥、计数和无残留锁断言均通过。锁与安全检查覆盖真实目录 ACL、目录和链接、空 PID 竞争、仍打开的外部观察句柄、文件被替换、释放权限错误及真实删除挂起。原 Cloud 使用量测试 18 项保持，预算、成本和日切实现没有放宽。

100 个请求的压力测试分别核对首波成功数与持久账本，仅接受精确的预算锁背压；之后显式用同一 ID 核对重试和回执幂等，最终使用 20 units、保留 500 units。它验证原子性，不承诺所有请求都在五秒内完成。Agent 的独立生产 gate 回归确认 BUSY 时不自动重试准入或发送 Google 请求，而是返回 30 秒保护提示。并发场景固定在 PT 日中且时钟继续流逝，独立 PT／DST 日切回归保留。令牌桶的逻辑边界用例另固定速率时刻，并显式推进两秒验证补充一个 unit；避免把慢磁盘期间的正常令牌补充误判为超支，生产补充规则没有调整。

CI 阶段日志记录到原生 helper 从 spawn 到 held 最慢 16.987 秒；原生测试有独立 20 秒总期限，不改变业务五秒期限。`npm test` 将常规回归与原生锁回归顺序运行，两组覆盖完整当前测试清单，锁文件内部六进程并发不变。旧账号测试现以真实本机清理方法完成落盘作为握手，并在任何断言失败后先排空 Executor／Runner，再恢复环境、删除临时目录；外部临时故障注入确认前例失败不会污染后例。清理确认丢失等反例保留，不以自动重跑掩盖失败。
