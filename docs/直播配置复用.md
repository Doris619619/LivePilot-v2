# 三步开播与直播配置包

## 使用流程

1. **素材选择**：选择循环视频、背景音乐，不显示预览或发布选项。
2. **直播编排**：选择配置包；编辑标题、说明、封面并可生成文案；完整配置默认收起，展开后可编辑全部本场素材、文案、封面与直播规则。
3. **开播**：显示最终预览与参数摘要，检查条件并开播。可返回修改，保留草稿。

完整配置不是另一份表单状态。`useInstance.selection` 是所有输入、最终预览及 `/api/control` 请求的共同来源。重复字段只使用不同 DOM 标识，直接同步。上传封面、生成文案期间锁定配置；退出第三步卸载预览。工作区切换保留草稿、步骤和上传任务。

客户工作台不再提供「连接与诊断」面板，也不展示频道 ID、Broadcast ID、Stream ID 等排障字段。后台快照、任务记录与状态接口保持不变。错误卡直接给出原因、处理说明和重新检查/重新授权等适用操作；「查看设备与频道」定位到实际连接区。未确认场次的核对与清理仅在异常时出现，仍要求人工确认，离线或操作中不可清理。异常的脱敏技术报告仍按需展开，供售后核对。

## 默认设置与配置包

「设置 → 直播默认」按登录账号管理公开范围、儿童选项、视频原声。首次默认公开、不面向儿童、原声关闭；只初始化没有既存数据的新草稿，不覆盖旧草稿或运行场次。

「设置 → 直播配置包」按设备、实例与频道管理规则：公开范围、儿童选项、视频原声、播放列表，以及互动开关、人设、描述和发送间隔。支持另存为、更新、重命名、删除。工作台第二步只选择套用；明确确认后只更新规则，保留素材、标题、说明和封面。撤销也保留套用之后编辑的文案。手动调整形成本场最终配置，不自动写回配置包。

设置中编辑包只刷新工作台的列表，不自动套用。初始化时旧草稿与运行场次优先；新草稿读取默认值，之后显式套用和手动编辑依操作顺序生效。

旧版本包仍可读取，无批量迁移；套用时只提取规则。新保存或更新规则时清空包中的文案、素材引用和封面引用，原素材文件与授权不删除。重命名保持原快照。每目标最多 50 套，名称最长 60 字且不重复。AI 观众互动纳入新配置包；旧包不含此字段时保留本场值。运行状态仅在开播后出现。

## 数据边界

- 配置包接口 `/api/broadcast-profiles` 按设备所有者、实例、已确认频道隔离；管理员协助使用设备所有者范围并记录审计，保存与删除检查修订号。
- `/api/broadcast-defaults` 按当前鉴权账号隔离，在数据目录下 `broadcast-defaults/<账号哈希>/defaults.json` 原子保存。严格 schema、同源校验、文件事务与修订号防止跨账号或并发覆盖。读取失败不会伪装成默认成功。不提供管理员代改其他客户默认值的入口。
- 不保存 API Key、OAuth、OBS 连接或机器路径，不发送开播命令，本场配置通过可选 liveChat 字段交给新版 Agent，旧版需升级。

## 直播编排与账号 AI（2026-10-16）

第二步统一命名为「直播编排」，互动四项参数在本场快捷区、完整配置和配置包中复用受控字段。开播请求携带完整参数，Agent 先应用参数再启动 OBS；运行中开关写回本场配置。回复不再加 `[AI]`，保留观众称呼与跟随留言语言。

账号 AI 服务由一个 Key 和两个用途开关组成，独立于设备选择。新增加密存储、所属设备读取、同步重试和旧版能力检查，原密钥文件与授权保留。详见 [AI 观众互动](直播AI观众互动.md)。隐私政策版本更新；旧发布任务的同意记录仍可读取，新任务沿用当前版本校验。

本次 `npm run verify` 通过：111 个测试文件、1055 项测试、8 项部署检查，类型、Lint、Next 和 Agent 构建通过。C 盘空间不足导致首轮上传/迁移测试失败，最终仅为验证进程设置 D 盘临时目录后通过，未修改系统环境。`tests/live-arrangement-ui.smoke.mjs` 验证双向同步、最终开播请求、账号用途开关、保存后清空密钥输入，以及 1440/390px 无溢出和无页面异常。Key 保存与开播在浏览器测试中拦截模拟，未调用真实服务。截图见 `screenshots/live-arrangement/`；原 UI 回归是前序证据，不冒充本次全部重跑。
