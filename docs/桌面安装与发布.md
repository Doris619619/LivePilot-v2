# 桌面安装与发布

## 与 Threadline 的对应关系

| Threadline 流程 | LiveNest 对应实现 |
| --- | --- |
| Electron + 独立静态桌面入口 | `desktop/app` + `electron/main.ts`，复用网站字体、CSS 和图标 |
| electron-builder + 当前用户 NSIS | `electron-builder.config.cjs`，目录选择、开始菜单和桌面快捷方式 |
| 预览 / 构建 / 发布 | `desktop:preview` / `desktop:build` / `desktop:release` |
| ASAR、受限 preload、fuses | 本地协议、sandbox/contextIsolation、IPC 白名单、禁用 RunAsNode/调试注入 |
| 构建清单与包后检查 | `build-manifest.json` + `scripts/desktop/smoke.mjs` |
| 版本标签触发 CI | `.github/workflows/desktop-release.yml` |
| 独立公开安装包仓库 | `Doris619619/LiveNest-Releases`，源码仓库可见性不变 |
| 草稿上传 → 回下载校验 → 公开 | `scripts/desktop/publish.mjs`，不覆盖公开版本 |
| electron-updater 手动下载/确认重启 | `electron/updates.ts`，关闭自动下载和退出自动安装 |

差别在于 LiveNest 还打包独立 Node、OBS 和离线帮助，必须保护远程直播。Electron 禁用 RunAsNode 后，Agent 用内置的 `vendor/node.exe` 运行，不依赖用户系统 Node。

## 本地开发与构建

开发机器需要 Windows x64、Git、符合 package.json engines 的 Node 和 npm；这些仅为开发依赖，不是导师电脑依赖。在仓库根目录执行：

```powershell
npm.cmd ci
npm.cmd run verify
npm.cmd run desktop:preview
```

预览输出 `release\preview\win-unpacked\LiveNest.exe`，必须保留整个目录，不支持自动更新。完整安装器：

```powershell
npm.cmd run desktop:build
```

交付 `release\LiveNest_0.1.0_x64-setup.exe`（文件名随版本变化）。同时生成 `.blockmap`、`latest.yml`、`build-manifest.json`。只有完整安装器给普通用户。

`desktop:renderer` 单独构建本地静态页面；`desktop:compile` 编译主进程、preload 与 Node Agent。临时本机开发验收可设置 `LIVENEST_TEST_DATA`；正式打包应用忽略此覆盖，避免生产身份被环境变量改写。

资源脚本固定获取 OBS 32.2.2 官方 Windows x64 ZIP 和 Node 22.23.1。OBS SHA-256 固定校验，Node 对照该版本官方 SHASUMS，再记录解压后 node.exe 摘要；缓存也重新校验。安装包包含第三方许可、字体 OFL 和 OBS 对应源码获取链接。OBS 不随客户端更新自动升级已有实例。

## CI 与公开更新源

1. 创建公开仓库 `Doris619619/LiveNest-Releases`，只放安装资产，不放生产配置和源码镜像。
2. 在 GitHub 创建仅能访问该发布仓库、具有 Contents 读写权限的 fine-grained token，存入**源码仓库 Actions Secret** `LIVENESTRELEASETOKEN`。不要把个人宽权限登录 token 复制到源码、客户端或日志。
3. 修改 `package.json` 版本并同步 lockfile，提交并完成验证。正式发布必须是干净提交。
4. 给该提交创建一致的稳定版本标签，例如 `v0.1.0`，推送标签。Windows CI 安装依赖 → verify → desktop:release。
5. 发布脚本核对来源仓库、tag、版本、提交和 clean manifest；生成草稿，上传安装器、blockmap、latest.yml，重新下载逐字节比较；全部匹配才公开。
6. 用户客户端匿名读取公开仓库，不内置 GitHub 发布 token。手动 workflow_dispatch 也必须选择匹配的版本标签。

缺少跨仓库 secret 会使自动发布失败；它不是客户端依赖。可先完成本地构建和安装验收，不能把本地构建成功写成 CI 已发布。不要上传包含本机身份的配置或测试数据。

## 更新与直播保护

启动约 30 秒后检查，后台每 6 小时检查，获得焦点和唤醒时最少间隔 1 小时补查。发现新版后用户在“设置 → 软件更新”点击下载，再确认“重启更新”。普通退出不安装，预览目录版不支持更新。

已配对设备更新、退出或变更实例前，客户端保存随机维护凭据，Agent 在有效会话内请求云端维护。云端与命令入队共用事务锁，要求所有实例状态新鲜、OBS 明确未推流、业务空闲、没有待完成任务、授权或上传。维护期间新开播请求被拒绝，避免检查后恰好收到开播命令。进程停止前排空任务；状态未知或维护未确认不强制重启。

维护凭据与配置原子加密保存，重启后恢复会话和心跳才释放维护。新增实例只追加或改显示名称，不删除旧 ID 与频道绑定。配置和媒体在安装目录之外，普通更新和卸载保留。

## 签名与安全边界

当前没有配置 Authenticode 代码签名证书。electron-builder 输出里的 signing 工具步骤不代表安装器已有受信任发布者签名，交付时应以 `Get-AuthenticodeSignature` 实测状态为准。若后续启用签名，应在 CI 配置证书凭据，不能提交私钥。

客户端固定使用本地静态资源与系统浏览器，远程内容不进入具有本机权限的窗口。Do 密码以带盐 scrypt 摘要校验，主进程校验每次读取/操作权限；会话不持久化，退出登录不结束 Agent。本地登录模块只内置摘要，输入密码不写入配置或日志。

## 验收命令与记录

```powershell
npm.cmd run verify
npm.cmd run desktop:build
npm.cmd run test:desktop:packaged
# 验收密码通过当前进程环境 LIVENEST_TEST_PASSWORD 提供，不写入 Git。
node scripts/desktop/acceptance.mjs --obs --multi
```

验收脚本启动真实 Electron，创建临时独立数据目录，检查未登录 IPC 拒绝、错误密码提示、登录/退出/重新登录、界面溢出、离线图片、真实 OBS 初始化、重复执行与多实例端口隔离。它不替用户进行 Google 同意或真实推流。截图输出到 `docs/desktop/screenshots`，真实状态与尚未验证项见[桌面验收记录](desktop/验证记录.md)。

完整验收还需要没有系统 Node/Git/Docker 的干净 Windows、两个已安装版本间更新与数据保留、远程配对与实际音画；任何未执行项必须保持未完成标记。先上线兼容云端，再分发桌面安装器。

## 主界面更新入口（开发分支，尚未发布）

对照 Threadline 的 `src/features/desktop-update/update-entry.tsx`、`update-controls.tsx` 及 `docs/desktop-auto-update.md`：LiveNest 顶部导航右侧只在发现新版本后显示“更新”。不增加全宽横幅，也不自动展开详情。点击入口后查看版本、进度和操作；外部点击、Escape 或关闭按钮收起。下载完成只将入口改成“重启更新”，由用户选择时机。

设置页与标题栏浮层共用更新动作。下载失败保留已发现版本和重试入口；没有已知新版的后台检查失败不弹出全局提醒。继续采用启动 30 秒、运行每 6 小时、窗口焦点/唤醒至少间隔一小时的检查规则。所有安装操作仍由宿主确认并取得本机空闲及云端维护许可，直播中、状态未知或任务未完成不能重启。

浏览器模拟验收命令：`npm.cmd run desktop:renderer` 后运行 `node scripts/desktop/feedback-acceptance.mjs`。模拟验证入口显隐、详情收起、进度、下载完成不弹出/不安装、错误重试及窄窗口；不代表两个真实安装版本间升级已验收。
