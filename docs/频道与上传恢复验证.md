# 频道与上传恢复验证

本次对应用户体验审计 F05、F09、F10、F15，并支持桌面实例改名、停用及坏 OBS 凭据的有限维护恢复。不涉及 F06 配额逻辑。

## 1. 频道换绑与取消

- 频道迁移仍先预占新频道，再由 Agent 保存加密授权，最后确认。预占返回 `claimId`，新版 Agent 在确认时回传。只有匹配最新预占的确认会释放同设备、同实例的旧频道，其他实例不受影响。
- `channel-claims.json` 是 Cloud 内部版本栅栏。先持久化栅栏，再释放旧绑定；写入失败可重试同一确认。迟到旧确认不能把已经迁移的频道抢回。预占或本机保存失败时，旧频道继续保留，不能交给其他目标。
- 旧 Agent 不带 `claimId` 时只能确认当前预占/当前频道；启动登记可以保留原频道而不取消正在进行的预占。已有历史重复行由 Agent 重新登记实际本机频道时归一。旧 Cloud 不返回 `claimId` 时新版 Agent 继续旧协议，完整迁移保护要求 Cloud 升级。
- 直播 OAuth 的维护活动改用 `oauth:<instanceId>:<beginTaskId>`，事务保存 begin 身份。明确取消只释放自己的活动，即使设备离线也不投递任务。成功 finish 回执按原始加密 Cookie 关联 begin，旧回调不能清掉后开标签页。旧单活动键仅由匹配最新 begin 的回调释放。
- 关掉授权页而没有回调仍保留原租约；失败或未知任务结果也不猜成已结束。取消原授权与撤销频道 Token 是不同动作，本次取消不修改本机现有 Token。

## 2. 素材上传

- 已完成记录的“上传下一个”只关闭本地面板会话，不发 DELETE、不要求原设备在线，也不删除已经发布到素材库的文件。
- 未完成上传的取消仍必须收到原设备的成功确认；离线失败保留原记录和恢复入口。
- 本地缓存与服务端恢复共用同一函数，目标、类型、权威偏移和进度同时切换，必须重新选择原 File，不能复用另一条记录的浏览器文件。
- 服务器恢复响应必须匹配列表中的上传 ID、设备和实例。未确认的创建意图会阻止切到其他恢复记录，避免丢失幂等身份。

## 3. 桌面库存和有限空闲证明

- Agent 会话认证下 `instance-rename {id,name}` 只修改显示名称，不改变路由 ID、不重启 OBS，也不需要全机维护。
- `instance-retire {id,token}` 仅用于非 main 且没有关联独立发布账号的实例，要求已获得维护凭据、当前推流和场次安全、没有在途任务/上传/OAuth、发布忙碌或未结束的目标任务。仍关联独立发布账号时保留原授权和工作，提示去发布模块核对处理，或恢复程序继续使用；不要求用户删除账号来恢复。
- 停用将实例和频道列表写入 `retired-instances.json`，在 registry 写入不可复用的 `retiredInstanceIds`，再释放该实例活跃频道绑定。文件、加密授权和发布历史保留；若释放写入失败，可凭原维护 token 幂等重试，旧在途绑定不能复活退休 ID。
- `instance-inventory {}` 是严格设备 Bearer、Host 和撤销校验下的只读核对，可在 session 前读取自身活跃实例及退休 ID。没有路径或授权信息。桌面在提交响应丢失后必须按此真实清单重连，不能把 404/未知响应当成空设备；旧 Cloud/Agent 不支持时应明确升级并保留待确认状态。
- `maintenance-begin` 可选 `verifiedIdle {instanceId,observedAt,basis}`，basis 只能是 `obs-status` 或 `process-stopped`。由桌面内部实际检查生成，经 Agent 身份提交，20 秒内仅替代该目标坏凭据造成的 `OBS streaming=null`。不替代 active/starting 场次、未确认创建意图、YouTube 错误/未知/直播，其他实例与队列保护完整保留。历史已停止场次允许明确 complete/missing/revoked 的平台证据。
- 此证明沿用 Agent 已有可信设备边界，不是浏览器声明或密码绕过；有 Origin 的浏览器请求、无 Bearer/会话的写入、过期/未来/错目标/非法 basis 均拒绝。
