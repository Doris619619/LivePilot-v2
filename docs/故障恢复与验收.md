# 故障恢复与验收

## 配置与维护

- 新实例先进入加密配置中的 candidates，正式 instances 不包含未验证候选。旧版遗留的 initialized=false 实例转入 candidates；已成功实例的 ID、密码、频道授权与媒体路径保留。
- 初始化失败后尝试恢复旧实例的维护状态；云端释放响应丢失则保留随机维护凭据。撤销候选只进入 archivedCandidates，不删除其配置、素材或 OBS 文件，也不停止该 OBS。
- 本地验证成功并保存正式清单后才向云端提交。清单提交响应丢失保留已验证实例和维护凭据，重连幂等同步，禁止撤销已经可能登记的实例。
- Agent 等待 spawn 成功才发送初始化，error、exit、close、disconnect 和发送回调错误均结算等待请求。通信失败但 PID 仍存活时禁止重复启动，不强杀运行中的 Agent。

## 离线退出

普通退出不再调用 maintenance-begin 或核对 OBS 是否停止；它仅停止接收新任务，排空本地已接收任务并等待 Agent 实际退出。托盘与应用退出事件复用同一请求，取消不做变更，确认前后均检查配置是否忙碌。排空超时保持客户端、任务和配置并允许稍后重试；不会强杀 OBS，也不会清理既有维护凭据。客户端内更新和 OBS 修复继续使用维护锁。

排空先等待接收日志落盘，再等待执行中的任务。同一轮询批次在每条任务前检查停止标志；停止后的迟到任务不继续接收，也不伪造完成报告。普通退出期间投递但未执行的任务留给云端核对。

## 电脑移除与恢复配对

网页电脑标题旁的“移除电脑”有就地确认，失败或响应不明保留重试入口。移除后从工作台隐藏并拒绝新通信；尚未派发的任务标记过期，已投递或结果不明的任务、上传活动、维护凭据继续保留；该设备的云端频道归属释放，可重新授权到任意电脑。移除不发送停止 OBS / 停播命令；应先在本机核对直播状态。

频道认领、移除和重新配对共用云端元数据锁。撤销先落盘，再释放频道占用；如果第二步落盘失败，重试移除、下一次认领或部署对账都会清理已撤销设备的遗留占用。重新配对先清理旧占用，不会复活历史绑定；普通断网和未知设备记录不按已移除处理。部署对账命令为 `LIVEPILOT_ENV_FILE=<云端配置> node dist/agent-admin.cjs release-removed-channels`，只修改云端归属表，不删除本机授权。

首次和恢复使用同一流程：网页生成新码 → 客户端粘贴 → 连接，无需选择原电脑。已有客户端提交原设备 ID 和长期凭据作为身份证明；云端在同一文件事务中消费新邀请并恢复原设备，返回实际设备 ID。网页通过邀请的 `pairedTo` 显示原电脑成功状态，不创建重复实例或迁移频道。

新码十分钟有效且只能被一台电脑认领；响应丢失后的同凭据、同原设备、同码重试返回原结果。再次移除原设备后旧收据不能恢复连接，必须使用新码。已认领的另一设备邀请不能被当作通用新码；错误旧凭据、过期码及并发第二认领均拒绝。原设备 ID、令牌、加密密钥、OBS 和维护记录保持。移除已释放的频道占用不会随配对恢复；旧电脑不能抢占已连接到别处的频道。只有从未在服务端登记成功的临时邀请 ID 可以改为新邀请 ID，仍沿用本机随机凭据和密钥。旧 Agent 不发送可选的 `currentAgentId` 时沿用原协议；旧客户端恢复入口保留。

客户端使用独立配对事务，先保存随机凭据再发请求；明确响应成功后才保存配对结果。重新连接等待新的心跳或错误，不拿旧认证错误立即终止。没有用重置身份、删除配置或重启 OBS 绕过失败。

## 电脑没有 OBS

安装包自带便携 OBS；“自动准备 OBS”不检查系统是否安装 OBS，也不依赖 PATH。缺少内置 ZIP 时，在创建实例文件前提示重新安装完整客户端；手动 OBS 文件不存在时提示恢复专用 OBS，或撤销候选再自动准备。只有解压后确认 obs64.exe 存在才写完成标记，部分解压可重试；已完成目录的程序丢失时提示检查文件与安全软件，不覆盖旧场景。检查电脑单独列出正式实例的程序文件可用性。

## 端口和密码修复

“修复连接（先关闭 OBS）”仅接受本客户端管理且 .livenest-owner 匹配的 OBS。目标必须确认已停止；直播、录制、无法认证但仍运行或进程检查失败时，不修改、不停止、不重启。用户在 OBS 确认停止并关闭窗口后可重试。

取得维护锁后再次检查进程状态，备份原 WebSocket JSON，保留无关字段和原密码；原端口可用时复用，被占用时选择空闲端口。配置保存后再启动验证。普通“启动并检查”只读取既有值，不自动轮换密码或重写配置；手动接入的旧 OBS 不进入此修复流程。

## 上传对账

- 沿用协议 1 的 upload-status / upload-cancel，无需旧 Agent 支持新任务类型。
- 创建、完成或取消任务失败后，云端以稳定查询 ID 发起对账；只有无在途任务且实际确认已完成、已取消、创建人的同一上传不存在或已过期时，才能清理维护活动。
- 创建未派发且已过期可以确认未执行；已投递但未知、设备离线、查询网络失败均保留阻塞。取消时拒绝仍有在途写任务的上传。
- 创建请求 ID 在浏览器发请求前保存。云端保留尚未结算上传的任务身份，“查询未结束的上传”可跨刷新恢复，按登录账号和设备过滤。
- 旧版若已清掉任务元数据、只留下活动 ID，页面显示归属待核查；没有归属或实际终态证据时不会自动解除。应使用原上传账号与目标查询，再取消已确认归属的上传。
- 维护错误分别说明上传、待核对任务、授权或设备状态；客户端仅显示受控维护错误，不透传原始 OBS / OAuth 数据。

## 网络隔离与依赖

桌面配对使用 Electron 系统网络，独立 Node Agent 只读取启动环境中的代理变量。2026-09-19 在用户 Windows 上复现：系统启用 HTTP 代理时，原内置 Node 直连健康接口报 ECONNRESET，同一 Node 沿用已有代理后返回 200；配对成功不能证明 Agent 已上线。

新版在 spawn 前通过 Electron `session.defaultSession.resolveProxy` 解析控制端地址，将系统 HTTP/HTTPS 代理传给 Node `--use-env-proxy`，用于 Agent 的 HTTPS 请求；显式 `https_proxy` / `HTTPS_PROXY` 优先，保留已有 NO_PROXY 并补充回环地址。不写系统代理、不保存代理地址到配置、不输出凭据；DIRECT 保持直连，SOCKS 或无效配置明确报错，解析最多等待十秒。PAC 返回的首选路由用于当前 Agent 进程，未实现逐目标 PAC 路由或代理认证交互；系统代理变化后需重新打开客户端。

Agent 返回连接错误后清除旧在线时间，并在下一次检查时结束“检查中”（约半秒），恢复重试入口；后台仍自动重连，现存活跃进程不会重复启动。网络失败才提示检查代理；凭据失效显示配对码入口，不再承诺重试可恢复授权。失败标题显示“连接未完成”。自动启动也记录连接活动，后续新鲜心跳可清除旧失败提示；维护尚未确认时仍保留恢复入口。旧 Agent 不提供错误码时保留原错误，不猜测原因。网页服务检查只证明桌面网络可达，上线仍必须等真实 Agent 心跳。参考 [Electron session](https://www.electronjs.org/docs/latest/api/session) 与 [Node 环境代理](https://nodejs.org/download/release/latest-jod/docs/api/http.html#built-in-proxy-support)。

客户端连接 127.0.0.1 不代表 OBS 只监听本机。检查电脑会读取 netstat 的实际本地监听地址；只有实际监听全为回环，或所有防火墙配置文件明确开启、默认阻止入站且没有可能匹配的入站允许规则时，才显示已验证。无监听显示待检查；权限不足、策略不明或可能允许外部访问均要求核查。该检查不添加规则、不放开端口，也不替代跨机器可达性验收。

Vitest 升至 4.1.11，修复 GHSA-82fw-gwwq-j7x9。原两项中危是 vitest 与 @vitest/mocker 同一开发服务器漏洞；未使用 audit fix --force。测试配置显式清理 mock 调用记录，兼容新版 restoreMocks 语义。
