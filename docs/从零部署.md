# 从拉取代码到可用控制台

这份流程适用于自己的 Ubuntu 24.04 服务器、域名和 Google 项目。不需要本次开发会话中的临时文件，也不要复制另一台电脑的账号、Token 或密钥。只想控制现有设备的同学，直接打开管理员提供的网址登录，不需要部署或安装 Agent。

## 0. 先准备自己的参数

| 参数 | 在哪里取得 | 保存位置 |
|---|---|---|
| 域名 | 自己注册的域名或 DuckDNS 子域名，例如 `studio-example.duckdns.org` | `.env.cloud`、`.env.agent` |
| 服务器 IPv4 | Lightsail 实例页面；不是你电脑/代理的出口 IP | DNS A 记录 |
| SSH 用户/私钥 | Ubuntu 通常是 `ubuntu`，私钥来自该区域 Lightsail | 自己的 SSH 客户端，不能提交 |
| ACME 联系邮箱 | 自己接收证书通知的邮箱 | Certbot 注册信息 |
| Google Client ID / Secret | 自己的 Google Cloud Web application 客户端 | 仅 `.env.agent` |
| agentId | 每台电脑一个稳定且不同的名字，例如 `studio_a` | `.env.agent` |
| OBS/素材路径、WebSocket 密码 | 对应 Windows 电脑上的 Portable OBS | 仅 `.env.agent` |

Node 使用 **22.23+（22 系列）或 24+**。首次部署需要 GitHub 仓库读取权限、服务器 sudo 权限、DNS 修改权限、Google 项目客户端编辑权限。仓库脚本不会购买服务器、自动提高配额或开通收费服务。小内存主机建议先提供至少 2 GiB swap 或在同架构 Linux 构建机验证构建；请留出发行版本、依赖和备份的磁盘空间。

本机通过 Cursor / VS Code Remote SSH 连接 Ubuntu 时，在 `C:/Users/<你的用户名>/.ssh/config` 追加（保留其他主机）：

```sshconfig
Host livepilot-cloud
    HostName 203.0.113.10
    User ubuntu
    Port 22
    IdentityFile C:/Users/<你的用户名>/.ssh/LightsailDefaultKey-us-east-2.pem
    IdentitiesOnly yes
```

把 IP、Windows 用户名、私钥文件名改为自己的值；日本区域的默认密钥文件名不同，必须使用该实例对应的密钥。先在 PowerShell 执行 `ssh livepilot-cloud`，核对服务器主机指纹后再使用编辑器连接。连接超时先查防火墙允许的公网出口；`no such identity` 表示文件名/路径不匹配，`Permission denied (publickey)` 再查用户名和实例密钥。

## 1. DNS：先指向服务器

DuckDNS 用户登录官网创建名字，在 `current ip` 填写**服务器公网 IPv4**，点击 `update ip`。留空会自动检测操作电脑出口，请勿这样做。没有可用服务器 IPv6 时保持 AAAA 为空；错误的 AAAA 也会导致证书验证失败。

也可以使用仓库命令。将 DuckDNS Token 单独保存到 `.data/duckdns-token.txt`（仅一行），不要写进命令历史：

```powershell
npm run dns:duckdns -- --domain studio-example.duckdns.org --ip 203.0.113.10 --token-file .data/duckdns-token.txt
# 上一步仅预览；核对自己的真实 IP 后发布：
npm run dns:duckdns -- --domain studio-example.duckdns.org --ip 203.0.113.10 --token-file .data/duckdns-token.txt --apply
```

`203.0.113.10` 是文档示例，必须替换。其他 DNS 提供商在自己的控制台建立 A 记录即可。脚本不会删除/自动修正已有 AAAA。服务器公网 IP 变化时，重新更新 DNS；本仓库没有后台 DDNS 自动更新任务。是否购买静态 IP、域名或套餐升级由账号持有人决定。

Lightsail 网络防火墙开放 TCP 80（ACME）和 443（网页/Agent）；SSH 22 仅允许管理员出口 IP 和必要的 Lightsail 浏览器 SSH。不要向公网开放 OBS WebSocket、3010 或 Windows 入站端口。也检查系统防火墙的同等规则。

## 2. Linux 云端：初始化、构建、部署

在服务器自己的交互终端克隆仓库。私有仓库先设置自己的 GitHub 登录，不要把 Token 放进 clone URL。

```bash
git clone https://github.com/Doris619619/LivePilot-v2.git
cd LivePilot-v2
# 安装 Ubuntu 依赖、官方 Node（校验 SHA256），已有 Node 不覆盖：
sudo bash deploy/bootstrap-ubuntu.sh 22.23.1
node --version
npm ci
npm run setup:cloud -- --domain studio-example.duckdns.org
```

生成 `.env.cloud`，包含随机云端加密密钥，重复执行保留原文件。不要把 Agent 的 Google/OBS 密码填到云端。生成的 `.data/setup/google-oauth.json` 是针对你的域名的 Google 配置清单。

先解析 DNS 并预览配置：

```bash
npm run deploy:render -- --env .env.cloud --node /usr/local/bin/node --certbot /usr/bin/certbot
# 预览 .data/deployment/generated，按实际 command -v node/certbot 调整上述路径。
```

确认域名解析、80/443 放通，并阅读 Let's Encrypt 当前服务条款（https://letsencrypt.org/repository/）后，执行：

```bash
sudo bash deploy/install-cloud.sh "$PWD/.env.cloud" you@example.com --agree-acme-terms
```

安装器会：

1. 校验域名、云端配置、干净 Git checkout；只打包受版本控制的文件。
2. 创建独立发行目录，在 Linux 执行 `npm ci` 和完整 `npm run verify`；失败不会切换现有服务。
3. 备份既有配置，为**精确域名**建立 HTTP 验证站点，申请 HTTPS 证书。
4. 短暂停止云端服务，备份持久数据，原子切换 `current`，安装单进程 systemd 和证书续期 timer。
5. 用正常 TLS 校验检查健康，再执行证书续期 dry-run；失败尝试恢复旧程序/配置，不回滚覆盖最新任务数据。

目录：`/opt/livepilot/releases`（程序）、`/opt/livepilot/current`（当前版本）、`/etc/livepilot/cloud.env`（root:livepilot 640）、`/var/lib/livepilot/data`（持久数据）、`/var/backups/livepilot/<时间>`（私有备份）。备份在同一台服务器上，请另外安排离机备份。不会自动删除旧发行版/备份；监测磁盘后由管理员清理。

**升级现有服务器**：拉取已合并代码，保留现有密钥和数据；安装器使用 `/etc/livepilot/cloud.env` 作为输入即可。它拒绝悄悄更换已有 origin、数据目录或密钥。发布会短暂中断云端访问；已接收的 Agent 任务继续执行。

```bash
git pull --ff-only
sudo bash deploy/install-cloud.sh /etc/livepilot/cloud.env you@example.com --agree-acme-terms
```

域名/服务器迁移请使用后文专门流程，不要用新随机 `.env.cloud` 覆盖旧实例。安装器管理名为 `livepilot` 的 Nginx 站点；若曾在该文件加入额外 IP 跳转或自定义路由，升级前移到独立站点文件或备份后重新应用。

1 GiB 主机如果没有 swap，可在首次部署前按需创建 2 GiB 文件（会占用现有磁盘，不购买额外资源）；已有 swap 时保留原配置：

```bash
free -h
swapon --show
# 仅在没有 swap、/swapfile 不存在且磁盘足够时执行：
sudo bash -eu <<'SH'
if swapon --noheadings --show | grep -q . || [ -e /swapfile ]; then
  echo '已有 swap 或 /swapfile，保留不改。'
  exit 0
fi
fallocate -l 2G /swapfile
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
if ! grep -qE '^/swapfile[[:space:]]' /etc/fstab; then
  echo '/swapfile none swap sw 0 0' >> /etc/fstab
fi
SH
```

## 3. 创建成员与配对设备

在云端执行（密码交互输入，配对码不要放进 PR）：

```bash
cd /opt/livepilot/current
sudo -u livepilot env LIVEPILOT_ENV_FILE=/etc/livepilot/cloud.env /usr/local/bin/node scripts/member.mjs create alice
sudo -u livepilot env LIVEPILOT_ENV_FILE=/etc/livepilot/cloud.env /usr/local/bin/node dist/agent-admin.cjs pair studio_a "直播电脑 A"
sudo -u livepilot env LIVEPILOT_ENV_FILE=/etc/livepilot/cloud.env /usr/local/bin/node dist/agent-admin.cjs list
```

Node 实际装在 `/usr/bin` 时替换路径。每台电脑配一个不同 agentId；同一电脑的实例清单可以有 `main,obs_a`。配对码十分钟过期、只能使用一次。先完成 Windows 安装与构建，再运行上面的 pair 命令生成配对码；现有 ID 不能用同一命令重新签发，重复执行不会刷新有效期。成员共享设备控制权限；只需看网页的同学创建成员账号即可。

## 4. Google OAuth：按生成清单设置一次

Google 普通 Web application 客户端的控制台配置需要项目持有人操作；仓库不会索取你的 Google 密码或绕过登录。`setup:cloud` / `setup:agent` 输出精确回调清单，按以下顺序完成：

1. 打开 https://console.cloud.google.com/ ，选择自己的项目；在 API Library 启用 **YouTube Data API v3**。
2. 打开 **Google Auth Platform → Audience**，配置应用受众。测试模式要加入实际授权的 Google 用户；品牌频道由有权限管理它的用户登录。测试模式刷新令牌可能短期过期，长期运行前按 Google 要求配置应用发布/验证，不能将反复授权当作部署成功。
3. **Clients → Web application**，新项目创建客户端；已有项目选择与你 `.env.agent` 的 `GOOGLE_CLIENT_ID` 完全一致的客户端。
4. 在 **Authorized redirect URIs** 添加生成清单中的地址，例如 `https://studio-example.duckdns.org/api/youtube/callback`。路径、协议、端口必须完全匹配。保留原有本机回调，尤其是 `http://127.0.0.1:3010/api/youtube/callback`。
5. 点击 Save，关闭重新进入确认地址仍在。Google 提示设置可能需要数分钟到数小时生效。本项目后端 OAuth 不要求添加 JavaScript origins。
6. Client ID/Secret 仅填写到每台 Agent 的私有配置，不能提交 Git。不要重建已有客户端或轮换 Secret 来修复回调拼写。
7. Agent 在线后，在云端选择正确设备和实例，点击连接频道，由频道持有人登录并同意。每个实例使用独立频道；不要跨设备重复绑定同一频道。

官方回调规则：https://developers.google.com/identity/protocols/oauth2/web-server#uri-validation 。普通公网 IP 不可替代域名。第三方免费子域名能否满足 Google 当前验证要求，以你的客户端控制台和真实授权结果为准；生成清单不等于 Google 已接受授权。

## 5. Windows Agent：新电脑和旧电脑分别处理

新手请完整阅读根目录的 [配置.md：新电脑接入与 OBS 配置图文教程](../配置.md)。其中明确给出 `C:\LivePilot` 目录、Node/Git 安装、Portable OBS 实机点击标注、Agent 配置、配对及验收。以下保留管理员命令速查；媒体根目录包含 `videos` 与 `music`。新电脑执行：

```powershell
git clone https://github.com/Doris619619/LivePilot-v2.git
cd LivePilot-v2
npm ci
npm run setup:agent -- --domain studio-example.duckdns.org --id studio_a
notepad .env.agent
npm run agent:build
npm run agent:pair
npm run agent:start
```

`.env.agent` 必须填写本机真实 OBS 路径、密码、媒体目录、Google Client ID/Secret。多实例按[首次上线前的配置说明](../配置.md#more-instances)处理，使用独立 OBS 目录和端口；已上线设备不可直接增删实例清单。配对命令会提示输入一次性配对码，请在 Windows 完成准备和构建后才由管理员生成，避免十分钟有效期耗尽。

旧本地服务改为 Agent：先停播、备份原 `.env.local` 和 `.data`、停止旧服务，再执行：

```powershell
npm run setup:agent -- --domain studio-example.duckdns.org --id studio_a --from .env.local
```

该命令保留旧密钥、频道令牌所在数据根和实例配置。检测到已配对的设备时拒绝重新初始化。已有 `.env.agent` 时直接保留，不尝试自动修复或换身份。

需要代理时，初始化可加 `--proxy http://127.0.0.1:7890`；已有配置可在 `.env.agent` 设置 `HTTPS_PROXY`、`HTTP_PROXY`、`NO_PROXY=localhost,127.0.0.1,::1`。不要猜端口，确认自己的代理监听地址。**`npm run agent:start`、`agent:pair` 和计划任务统一在启动前加载代理**。不修改系统代理；OBS 的 RTMPS 网络设置独立于 Agent。

验证后按需安装当前用户登录自启（不会立即开播）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/install-agent-task.ps1
```

任务名默认 `LivePilot-Agent`。如已有同名任务，先检查旧任务配置再处理；不要同时运行两个 Agent。注销 Windows 会终止交互会话，第一版不支持 Session 0 自动启动桌面 OBS。只有手动启动 Agent 时，关闭其终端会停止 Agent 通信。

## 6. 一次完整验收

```powershell
# 有代理时，诊断也必须在进程启动前加载配置：
node --env-file=.env.agent --use-env-proxy scripts/doctor.mjs --env .env.agent --ip 203.0.113.10
# 只检查本机配置，不访问网络：
npm run doctor -- --env .env.agent --offline
```

云端可运行 `npm run doctor -- --env .env.cloud --ip <服务器IP>`。缺配置/未配对/网络失败返回非零；首次配置时照提示补齐再运行。健康检查只证明 HTTP 服务可用，不证明设备在线。

按顺序验收：HTTPS 无证书警告 → 成员登录 → 正确设备在线且状态更新 → 每个频道 Connected → 小文件上传到正确电脑 → 由用户发起一条测试直播并看实际音画 → 正常停播 → 第二设备同名实例隔离 → 中断控制端连接后任务继续且重连不重复。真实授权和开停播必须由用户参与/授权，不能用 CI 替代。

Linux 运维检查：

```bash
systemctl status livepilot nginx livepilot-cert-renew.timer --no-pager
journalctl -u livepilot -n 50 --no-pager
df -h /var/lib/livepilot
sudo certbot renew --dry-run
```

## 7. 故障、域名迁移与回退

| 情况 | 处理 |
|---|---|
| HTTPS 验证 404 | DNS A/AAAA、80、防火墙和 Nginx `server_name`/webroot 必须匹配；先 `nginx -t` |
| 登录 403 | 页面域名须等于 cloud.env 的 `LIVEPILOT_ORIGIN`，代理保留 Host；不要放宽同源校验 |
| Google redirect_uri_mismatch | 按生成清单核对同一个 Client ID，保存后重新进入确认，等待生效 |
| 网页可打开、设备离线 | 查看 Agent、代理进程及日志；不代表 OBS 已停播 |
| host.lock | 确认旧进程退出后，使用 `LIVEPILOT_ENV_FILE=.env.agent` 配合 `recover:lock -- main host`；不删状态和令牌 |
| 配对身份与域名不一致 | 停止 Agent，备份后同步 `.env.agent` origin 和 `.data/agent/identity.json` origin；保留 id/token；确认新控制端持有原设备目录后重启 |
| 旧场次已 complete、记录仍 live | 使用原频道核对实际状态，通过“结束直播”收尾；不清空 `.data` |

换服务器保持同一域名：先备份云端 env/数据，复制到新服务器并保持密钥、成员与设备记录；停止旧云端写入后做最终一致副本，再切 DNS，验证新服务后才能删除旧资源。不要让新旧云端长期同时接受写入。Agent 已接收的任务继续执行。

换域名：先准备 DNS 和证书，备份 cloud.env/Nginx/Agent 配置及设备身份；在无执行中任务时同步 cloud origin、Agent origin/identity origin 和 Google 回调，保留旧入口 HTTPS 证书并配置跳转。切换后需要在新域名重新登录。不要发送设备凭据到重定向目标，Agent 始终直接连接已配置的新 origin。

回退程序：保留当前数据与加密密钥，记录现有 `readlink -f /opt/livepilot/current`，将 symlink 切回已验证的发行目录，`systemctl restart livepilot`，再检查 HTTPS/设备状态。跨存储格式升级需先做兼容审查，不能仅恢复旧 data.tgz 覆盖最新任务。旧备份含敏感凭据，禁止上传 PR。
